# 主日 PPT 讀經與詩歌排版

正文使用模板原有中文字型（目前是 DengXian），包含東亞字型設定。讀經、詩歌正文上限均為 **30 pt**，同頁正文使用相同字號。頁首、頁碼、讀經交接提示與其他模板內容維持原樣。

排版由 `backend/ppt_text_layout.py` 集中處理，不由模型選字號：

- 讀經按文字框可用寬高、實際字型字寬、換行、行距與段間距，從 30 pt 向下尋找可放入的整數字號；一節內可換行。
- 詩歌按每一原始行的完整寬度量測，關閉自動換行。若某行放不下，整頁一起縮字；不改原行，不自行拆成額外行或額外 slide。空行分頁仍由原有流程負責。
- 使用已安裝、與模板相符的粗體字型量測；Office 在 Mac 的 DFonts 也納入搜尋。`SUNDAY_PPT_FONT_FILE` 可指定同字型檔案。找不到時採用較保守的字寬估計，但不擅自改用另一種字型。
- 明確寫入每段與每個 run 的字號，清理殘留段末字型、縮排及自動放大設定。文字框位置與尺寸不變，讀經白／黃交替、詩歌置中保留。
- 節號以 DrawingML baseline 保存上標，不使用 python-pptx 不支援的動態 `Font.superscript` 屬性；不再額外縮小一次，避免渲染器重複縮小。
- 為投影可讀性設 18 pt 下限。極端內容在這個範圍仍放不下時，回報可理解的排版錯誤，要求調整換行／分頁，不產生溢出或持續縮成小字的 PPT。API 將此視為待調整資料（400）。

一般字型、形狀及段落設定使用 python-pptx 公開介面；中文東亞字型、節號 baseline、合併表格格線範圍等缺少公開介面的部分集中在此模組處理。原有重複的讀經交接函式及不可達的詩歌分支已移除。保留既有產生器、模板、同工分配及經文／詩歌資料來源。

驗證包含中文／英文、長行、長段落、段末殘留字號、表格與合併格、PPTX 保存後回讀。另用私有的 11/1 真實內容比較生成前後：文字與原分頁不變，兩張讀經為 23／20 pt，詩歌為 30 pt。使用實際 Office DengXian 字型進行 LibreOffice PDF 渲染，檢查文字邊界及詩歌行數；這不替代 PowerPoint 本身的跨平台渲染驗證。
