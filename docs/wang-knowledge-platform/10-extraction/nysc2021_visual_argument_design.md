## 1. 目標與範圍

系列為 [2021 NYSC 專題：馬太福音釋經（八)](https://dallas-hlc.org/resources/series/2021%20NYSC%20專題：馬太福音釋經（八))。來源 item 依原目錄為「2021 NYSC 專題：馬太福音釋經（八）王守仁 教授 4之1」至「4之4」，括號與檔名以 API 身分為準。四講按原順序組成閱讀範圍。讀者應能從論證層還原教授的提問、經文比較、原文判斷、圖表推理、反駁、限定與結論，並回到實際原段或 SVG。

開發及驗收沿用 [#845 的單元論證設計](./unit_argument_design.md)。先讀完整系列劃單元，再按問題細讀分組，最後連起各支推理。單元可跨講，同一題可以中斷後續講。每組保留總括 Claim 及下層判斷，每個原講保留自身 Claim 身分。產量由教導內容決定。

## 2. 來源準備與 API 邊界

統一消費 [argument-source-package.v1](./argument_source_api_design_v1.md)。同機讀取使用同一 Python builder，遠端使用經認證的 HTTP 介面。論證端只消費合約，儲存路徑由來源層處理。

每講封存完整來源包、item、口述與視覺版本，以及逐一 SVG 的 locator、asset、原圖及 SVG 雜湊、群組、段落與時間。來源包快照為該次模型實際材料，保留未准入項及原因。後續來源包或 SVG 改版時，只續用精確相同的材料及回答；受影響的生成和審查重新綁定。

資料現況與參考版本列於 [Eval 的首講 key](./nysc2021_visual_argument_eval.md)。在實跑前須處理下列已見問題。

- 首講 API 仍回傳整段以刪除線標記的主持介紹，段內也有局部軟刪內容。接入須使用正式 Editor 已有的可見正文語義，保留原 paragraph ID、來源版本及原文位置。校對附加的逐字稿內投影片抄文，其歸屬須辨明，避免另當教授口述。
- 各講的群組為待確認狀態，不能以無 pending 為假設開始抽取。沿用已核准的篩選與確認規則，記錄 pending 原因、確認所綁版本及其影響。預覽參數的結果保持預覽身分。若現行確認流程需要調整，先修改其設計並取得負責人決定。
- 投影片重要度沿用既有四類及排除規則，核對選擇結果是否真正落到 API 的 hidden／可見群組。源包列出的群組數不代表全部符合來源資格。無法綁定口述段落者留下具體缺口。

## 3. 重要 SVG 如何進入模型材料

依[既有圖像來源規範第 4 節](../20-knowledge/diagram_source_fragment_solution.md#4-他的圖和投影片來源片段)，教授自己的圖和帶其註記的經文頁可作視覺來源。純經文及書頁沿用引用身分，整理圖保留編輯歸屬。重要度由既有 `slide_editor_alignment` 的判準決定，來源准入另核對圖像轉換審查及確認的實際版本。

每個單元取入其口述範圍所解釋的視覺事件，保留實際出現時間和解說段落兩種定位。提前換頁、重現同一圖、逐步新增內容各有事件身分。相同資產可以共用 SVG，獨立解說步驟仍保留。跨段使用同一張圖時，以引用重用，維持原話與畫面次序。

每次把 SVG 交給生成模型，都在模型可讀的輸入中明列該圖的事件 locator、所屬講次、對應的原 paragraph ID 及其可見原文。多圖可指向同一段，一次解說延續數段時逐段標明；段落原文在同一請求中可按 ID 共用。保留 API 的排版錨點 `before_paragraph_id`；遇到提前換頁或延後解說，另標出有原話支持的解說段。解說位置未能確定時標為待定位。

生成材料提供 SVG 的可見文字與結構、定位及口述。延伸既有 `SourceProjection`、`VisualSourceBlock` 和 `svg_diagram`。需要從圖形判讀的布局、箭頭、顏色或重疊若超出現有讀取能力，就向該階段模型提供由固定 SVG 渲染的圖片並綁定來源版本，留下讀圖與原圖核對結果。API 的 `reason` 或 `helps_reader_understand` 僅為選材註記，不能充當教授原話或支持結論的證據。

在系列切分、組內抽取及單元連線三處均傳遞相關視覺內容。凡推理依賴圖上的關係，模型須在相應的證據步驟或論證關係中用文字寫出哪些項目如何相連，以及教授如何用它支持這一步，分別引用視覺事件與解說原段。口述已清楚表達同一關係時，共用該步文字並補上圖的引用。圖上替反方整理的七年時間線須保留被反駁者歸屬。希臘文、否定、色彩區分與箭頭方向納入忠實性核查。

## 4. 引用、來源身分與入庫

現有 `claim_unit_plan` 讀舊 JSON 並用 S 序號定位，新的來源包保留 Editor paragraph ID。接入建立明示對照，保留舊來源的正常入口。API 來源的單元範圍、每句和每個視覺事件皆綁原 item 及版本，禁止以相似 ID 合併不同講。

現有 `extract_claims` 只允許口述 conclusion anchor。視覺來源沿用已有 visual fragment 欄位，將原 SVG 及其 locator、雜湊作為可核對的來源，圖上可見文字或結構另供閱讀。Claim 若由圖與口述共同支持，分別保留兩項證據及其作用。不得把程式產生的圖像描述當作逐字口述，也不能為符合原有格式而虛構一段講話。

擴充 `unit_argument_candidate_v1` 的視覺來源表示時，同步更新 bind、fidelity adapter、round-trip projection、loader 與 reader，維持既有純口述候選可讀。視覺片段落在實際原講，跨講關係另存支持邊。寫入沿用既有單元 loader、短 transaction、版本歷史及回讀驗證；候選、審核與入庫狀態各綁實際版本。

## 5. Eval

詳細 criteria、首講參考答案草稿與計分見 [Eval](./nysc2021_visual_argument_eval.md)。先由負責人確認 criteria 和 key，再凍結來源與提示開始模型實跑。參考答案供評審讀取，生成器只收到來源與通用任務。

Claim verification 與 round-trip verification 每個待交付單元都做。前者逐條核對節點及關係對應的口述或 SVG；後者由獨立讀者只看論證層，再由另一廠商模型對照完整口述及視覺來源，核對完整性。歸因分清圖中遺漏、錯接與重構失誤。報告、審核和頁面須驗證其候選、正文及視覺版本，才可合併顯示。

四講生成後，逐講列出已分配、未分配、排除及待判來源。每個重要投影片事件須有被使用、重用、排除或未解的具體記錄。全部聲稱完成的單元都須通過來源校驗、兩項內容核查與入庫回讀。

## 6. 設計自審與待確認事項

- 輸入端有投影片，不保證各階段讀到了它。評測必查實際保存請求中的 SVG locator 和內容。
- 本系列有大量對反方觀點的轉述。圖表中的「空中／地上」分類須連同講者批評的作用理解，避免單獨抽成教授認可兩階段的 Claim。
- 後三講內容及其細部答案尚待獨立閱讀。本次首講 key 為草稿，未簽定。後續另取一個非首講的完整單元驗證凍結流程。
- 來源確認、軟刪投影及視覺片段欄位是接入工作的一部分；把問題具體修到來源層或適配層，再用原始資料驗證。已有資料／審查不得由程式補成通過。
