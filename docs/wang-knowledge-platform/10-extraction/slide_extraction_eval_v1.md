# 投影片抽取與白底 SVG 改進 Eval v1

> **讀者**：Developer、Solution architect
> **類型**：規範
> **狀態**：當前
> **與代碼對齊**：2026-11-27（核對到 `wkp-472-transcript-slide-pilot` 工作區）
> **權威範圍**：#472 投影片偵測去重、視覺文字抽取與白底 SVG 重建的驗收標準、基準講道 Key 與計分方式。

## 1. Criteria

每條標準皆可獨立檢查：

1. **只落盤候選幀與去重**：偵測階段不對全片每 500ms 全量寫入 JPEG；僅保留切換候選與必要上下文圖。進入視覺抽取前，以感知哈希（pHash/dHash）對裁剪投影片去重，因壓縮雜訊或切回舊頁而內容實質相同的畫面不重複抽取。
2. **切換偵測準確率**：不漏掉實質新投影片（`new_slide`）、逐條增減（`build`）與有意義的標示變化（`emphasis`）；不把純講者畫面、滑鼠游標移動或 2 秒內的過場閃爍誤判為換頁。
3. **文字與希臘文忠實度**：繁體中文、經文出處與希臘文／希伯來文變音符號（如 `ἐκλογή`、`αὐτῷ`、`παραπτώματι`）逐字還原，不因語音或聖經知識改字，不出現截斷腰斬；忽略 PowerPoint 底部導航列與游標。
4. **全投影片白底 SVG 輸出**：每張去重後的有效投影片（包含純文字頁與圖表頁）皆產出可解析的 SVG，畫布背景為純白（`#FFFFFF`），文字與圖元不重疊、不超出畫布邊界。
5. **白底對比度與語意色調保留**：原深色背景上的淺色字體自動映射為白底高對比深色（WCAG 對比度 ≥ 4.5:1），並保留教授原有的語意分色對比（例如白字→深炭黑、黃字→深琥珀、綠字→深綠）。
6. **獨立原圖 Fidelity 核對**：獨立覆核呼叫（不帶逐字稿）對照原圖與抽取文字／白底 SVG，能檢出漏字、截斷、希臘文變音符號錯誤或圖表連線錯誤；不自動改字。
7. **重要投影片篩選與段落綁定**：
   - 純經文頁（無教授註記或結構排列）、封面、過場與冗餘逐步顯示（`redundant_build`）標為不進正式 Editor，且純經文頁絕不標為 `source`（僅作 `scripture_reference_only`）。
   - 入選的重要投影片必須綁定到教授實際解釋它的逐字稿段落，並能以一句話回答「它幫讀者看懂哪一段的什麼？」。

## 3. Grading

每輪試跑固定報告以下量化指標（不以主觀印象代替）：

1. **偵測與去重**：`candidate_count`、pHash 去重數、與舊流程 `<2s` 重複幀對比、磁碟寫入圖片數。
2. **文字抽取（抽樣與對照）**：對照舊流程 9 張已抽文字投影片，報告「修復截斷數」、「修復希臘文／字元數」、「新增漏抽投影片數」。
3. **白底 SVG 品質**：`svg_generated_count / unique_slide_count`（目標 100%）、`#FFFFFF` 背景驗證通過率、前景色對比度（≥ 4.5:1）通過率、XML 可解析率。
4. **Fidelity 與段落綁定**：原圖 Fidelity 通過數／標出差異數、純經文頁排除率、重要投影片段落綁定準確率（人工抽檢對齊實際講解段落）。
5. **成本與時耗**：API 呼叫次數、預估費用上限（USD）、總處理時間。
