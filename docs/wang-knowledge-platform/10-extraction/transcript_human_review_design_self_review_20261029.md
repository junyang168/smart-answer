## 1 已核對的使用者要求

- 使用原講道 editor，流程維持認領、逐段聽／看與 Markdown 校對、發佈、最後取消認領。
- 每篇同時只能一位認領人修改；管理員需明確接手，不能平行繞過。
- 所有修改自動儲存，包括若保留的標題與簡介欄位。
- 自動 slide 替代手動加圖；AI 問答移除。
- 編輯歷史必須保留且可查看；歷史恢復單獨標為新增選配。
- 其他小功能先列清單供使用者選擇，未代替其決定。

## 6 現有逐字稿儲存格式相容

2026-10-29，使用者明確要求儲存與現有逐字稿相容。取消前版以 current bundle 取代草稿主本的決定：正文繼續使用 script_review 段落陣列及 script_published 的 metadata/script；時間 entries、處理基線與 Markdown 亦保留既有格式。新資料另存 context，不複製另一份現行口述正文。

本次自審檢查三個連帶風險。第一，舊時間公式無法使用 w00-p...，因此新匯入採穩定數字 index 與原片絕對 entries，毫秒另存；既有人工稿不重編號。第二，多檔保存不能宣稱單檔原子性已足夠，加入預寫操作、提交回執與讀寫前恢復；第三，舊保存請求省略新欄位時不得丟附屬資料，全部寫入口須走共用相容服務。

設計第 4、5、6、7、8、9、10、12 節已同步調整；新增以真正舊讀取、保存與發佈器往返驗證的驗收，未把 JSON 可解析當相容通過。先前自審中有關單一 bundle 權威的結論由本節及更新設計取代。這些仍是待實作設計，沒有變更任何逐字稿資料。更新後設計檔 SHA256：`1c3339881a171985542c6359dab6abe303ab8b8e1c6efda20d69c231603d0a84`。
