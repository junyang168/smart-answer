# 圖文逐字稿同工審核設計

> **讀者**：Solution architect、Developer、負責校對的同工
> **類型**：規範
> **狀態**：當前設計，尚未實作；第 12 節小功能清單待使用者選擇
> **與代碼對齊**：2026-10-29（現況核對到 `def000a2`；下述目標行為尚未實作）
> **權威範圍**：新視頻圖文逐字稿接入既有講道編輯器的審核、儲存與發佈契約；不批准文庫主張、不改變平台使命或來源准入規則。

同工繼續使用既有講道編輯頁面：**認領 → 分段聽／看並修改 → 發佈逐字稿 → 取消認領**。文字、投影片辨識內容、代表圖及位置的修改全部自動儲存；發佈是另外一個明確動作。已發佈的版本保持穩定，直到同工再次發佈新版。

本設計擴充既有 `/admin/surmons/[item]`，移除 AI 問答與手動加 slide 的入口，直接帶入處理好的圖文候選。原圖片、實際出現時間、機器修改紀錄與人工決定均保留；投影片文字始終標明非口述。

## 2 同工的操作流程

### 2.1 認領及載入

同工在原講道列表認領，進入原編輯頁面。服務端以登入身份及既有 ACL 判定權限；同一篇同時只能有一名認領人，管理員操作仍依原權限處理。兩人同時認領，只能有一人成功，另一人看見最新認領資訊。

新 pipeline 先產生獨立候選。採用是當前認領人的明確動作，服務端仍檢查當前權限；不在認領時偷偷覆寫稿件。有人工修改的 review 或已發佈版本時，預設保留；服務端比對採用時的基線版本，衝突即拒絕。第一版不提供把整份候選強行覆蓋人工稿的捷徑。

已採用的候選包含口述、全片時間、完整代表圖、OCR 與分組排版。進入審核頁後直接可用，不要求同工手動找圖或重建來源資料。

### 2.2 分段核對

左側保留影片／音訊播放器；右側保留逐段稿件與 Markdown 編輯器。沿用點選定位、雙擊編輯、段落末暫停、前後五秒；書籤等輔助功能是否保留見第 12 節。影片可以在該講道有對應音訊時切換音訊，切換保留全片播放位置；沒有音訊來源時不顯示切換選項。

每段顯示「待核對／已核對／有疑問」。同工聽／看並修改後，可按「確認並下一段」；該動作自動儲存確認狀態，再選中下一段。仍保留原有自由選段及書籤操作，不強迫依序播放。

確認不要求系統追蹤完整收聽時長。同工負責實際核對；系統記錄其明確決定及所確認的內容版本。之後修改該段文字或時間，就使該段舊確認失效；不讓無關段落的修改重置全篇進度。

### 2.3 審核自動帶入的投影片

代表圖顯示在最相關段落之前。點開可核對原圖、OCR、原片時間與該組逐步畫面。OCR 使用獨立文字編輯欄位，標示「投影片文字，非口述」，修改自動儲存。同工可以更換本組的真實代表畫面、選擇放在哪一段之前，以及隱藏錯配圖片；不需要編寫 SVG。

「調整位置」以選擇段落為基本操作，鍵盤也能完成；拖曳僅是輔助。變更代表圖、來源文字或位置後，對應確認失效。位置是編輯安排，不改變圖片原來的出現時間，也不更改段落聲音時間。

同頁逐步顯示保留一張完整代表圖；重返舊頁另保留事件。若中間狀態含後來消失的文字、遮蔽、否定、箭頭或論證步驟，介面要突出差異，不能因末頁完整就把它們視為無內容的重複。原片沒有 slide 的區間保持空白。

本組的確認範圍必須明示：代表圖、OCR、閱讀位置及已列出的獨有中間內容。原圖不能看清的地方保留不確定標記；不得要求同工猜出希臘文／希伯來文。SVG 有問題可切回原圖，並把轉繪標為未核實。確認代表圖不會自動批准所有歷史畫面或 SVG。

隱藏只改閱讀展示，不刪除來源。每個未展示狀態仍需有處置，例如逐步重複、快速跳過、回顧或待釐清；不得把「不展示」直接當成「教授沒有教過」。

### 2.4 完成及離開

頁首顯示未核對段落、未處理圖片及有疑問項目的數量，並能直接跳至該項。自動儲存不增加「儲存」按鈕；發佈仍是主動操作。

首次發佈新版格式時，所有保留口述段落必須已確認；每組圖片有明確處置。有疑問的口述須先解決；不確定 OCR 可以隨原圖明示保留，但不能當成已核實視覺證據。系統不因 SVG 未核實就禁止發佈原圖閱讀版。

發佈成功後顯示完成版本連結，同工最後再取消認領。取消認領不自動發佈，也不撤銷已發佈版本。未完成也可在修改已同步後取消認領，讓下一位接手；保留其修改、進度及審核者身份。

## 3 工作狀態與權限

把「誰在工作」「稿件進度」「公眾看到哪個版本」分開保存。

| 狀態 | 權威資料 | 轉換規則 |
| --- | --- | --- |
| 認領 | 既有講道 metadata 的 `assigned_to` 與新增 `assignment_epoch` | epoch 是每次認領、取消或轉交都更換的工作代號，阻止舊分頁延遲提交 |
| 審核稿 | 新 review bundle，見第 4 節 | 修改、段落確認、OCR 與位置均是草稿；未發佈時不改公開內容 |
| 發佈版本 | `script_published/<item>.json` 指向的完整版本 | 只有成功發佈才能替換；認領及取消不改它 |

metadata 的 `status` 先保留給舊畫面相容顯示：有有效公開快照時維持 `published`，認領人另外顯示；未發佈時才投影為 `ready/assigned/in review`。新 UI 的「已發佈，另有修改中草稿」依兩份版本比較產生，不能只讀一個 status。

**每篇講道同一時間只有一位認領人可以寫入**，涵蓋口述、OCR、代表圖、位置、審核決定、歷史恢復，以及決定保留的標題／簡介等 metadata。其他同工只能依既有可讀權限查看。管理員不得以 write-any 權限繞過此規則；若要修改，必須先經明確轉交命令接手，原認領人的工作代號立即失效。管理員的發佈操作仍受既有角色權限限制，本設計不擴張其發佈權。公開讀取一律選最後已發佈快照，沒有快照便明確回覆尚未發佈，不以 review 草稿代替。編輯預覽使用獨立受權限保護的路由。每個修改、確認、採用、發佈及取消請求都由服務端重新檢查身份、權限及工作代號，不能相信前端傳入的 user_id 或按鈕顯示。

有效公開快照指成功發佈回執所指定、且仍可公開的版本，不能只因 published 檔案存在就推定公開。legacy 接入時以當時明確的 `published` 狀態及有效檔案建立公開基線；原本非公開、但殘留歷史 published 檔的講道，不得被遷移或取消認領重新公開。正式撤稿是另一路受權限控制的操作，不由取消認領代替；本版不新增撤稿 UI。

認領是可持續數天的工作安排，不是自動到期的短租約。關閉瀏覽器不取消認領；管理員可按既有權限明確轉交。同一認領人開兩個分頁不會產生第二位編輯者，但仍需版本衝突保護，避免自己的舊分頁覆蓋新版。背景 pipeline 在認領期間不能寫入人工稿。

## 4 資料與來源身份

### 4.1 一份可原子更新的審核資料

對新格式採用一個 `transcript-review-bundle.v1`，存於 `$DATA_BASE_DIR/transcript_review/<item>/current.json`。bundle 指一次完整審核稿，包含口述、圖片引用、閱讀位置與審核紀錄；不存影片或圖片二進位。

這是新格式唯一的草稿寫入權威。舊 `script_review` 保持原有格式，不能再同步寫成第二份可編輯權威；所有編輯、metadata、加標題與候選採用入口先經共用 resolver，明確選擇 bundle 或 legacy。尚未支援 bundle 的寫入入口返回可識別錯誤，不可悄悄寫到舊檔。

| 欄位 | 內容 |
| --- | --- |
| `item/schema_version/source_run` | 講道身份、格式版本、不可變 pipeline 執行紀錄及其 SHA |
| `editorial_metadata` | 若第 12 節決定保留標題／摘要等編輯欄位，這些草稿值亦放入同一 bundle，不直接改公開 metadata |
| `paragraphs` | 穩定 paragraph ID、Markdown 口述、全片 `start_ms/end_ms`、來源 ID 與修改紀錄 |
| `visual_assets/occurrences` | 原圖、OCR、圖元與 SVG 的版本引用；每次真實出現的時間與來源影格，不因排版改動 |
| `reading_layout` | 連續狀態分組、代表圖、`before_paragraph_id`、顯示或隱藏及理由 |
| `reviews` | 審核對象、所確認內容的 SHA、決定、審核者與服務端時間；區分口述、OCR、SVG 與排版 |
| `revision/operation_receipts` | 單調增加的修訂號、已套用操作的識別及結果，用於重試核對 |

檔案原始 bytes 的 SHA 作為強版本標記；不把自身 SHA 寫進自身造成循環。每次保存先寫不可變 revision，再原子替換 current，回傳新版本；不可變 revision 可供歷史比較。發佈引用已持久保存的 revision，不能引用會繼續變動的 current。

revision 檔先完成不等於已提交；current 的原子替換才是草稿提交點。修訂檔記錄父版本 SHA，回執只從 current 或已發佈版本可達的修訂鏈核對。崩潰留下、未被任何提交引用的修訂，不得被當成已保存成功。

原始 ASR、模型校字／刪除紀錄、圖片、原影格及 pipeline 時間檢查保持不可變。人工修改新增自己的版本，不改寫機器曾經輸出什麼。

### 4.2 時間、段落與圖片綁定

新格式一律保存原片絕對毫秒；播放器只在邊界轉為秒，保留小數。服務端不得再按 window ID 或二十分鐘分塊推算。`w00-p...` 是身份，不是時間公式。舊格式繼續用舊解析器，以明確 schema 選路，不憑 index 長相猜測。

圖片有三種獨立位置：`time_ms` 為原片變化、`capture_ms` 為實際擷取影格、`before_paragraph_id` 為閱讀位置。文庫引用的影片時間取前兩者，不能把提前展示的完整 slide 說成教授當時已全部顯示。

第一版在同一 Markdown 段落內換行不改 paragraph ID，也不自動改聲音時間。先沿用既有段落編輯能力，不新增任意拆分／合併段落。後續若新增結構編輯，必須同時保存新舊 ID 關係、重新處理時間與 slide 綁定，再使受影響確認失效。

### 4.3 審核失效範圍

口述確認綁文字及聲音區間；OCR 確認綁原圖、區域及逐字內容；SVG 確認另綁精確轉繪 bytes 與其原圖；排版確認綁代表圖及目標段落。移動圖片不使口述確認失效，修改 OCR 也不使全篇口述重審。

同工調整字體或程式修復 SVG 時，不得把舊 raw SVG SHA 的確認直接搬到新 SHA。第一版重新確認該轉繪即可，原圖及口述核對可以保留。

## 5 自動儲存與編輯歷史

### 5.1 寫入與回應

文字、OCR、代表圖、位置、隱藏、審核狀態及決定保留的講道資料欄位均走同一自動儲存佇列。第一版採用停筆約一秒後同步的可調 debounce；這是設計初值，需用實際輸入測試確認。中文輸入法組字中不提交未完成組字；組字完成後排入保存。

前端把一次「確認」綁定按下時的內容快照；若其後又輸入，後續操作必須把確認重置，不可將舊確認挪到新文字。

同一篇每個分頁只容許一筆寫入在途，後續修改合併成下一筆操作。每筆附 `operation_id`、預期版本與工作代號。服務端在鎖內比對後一次寫入完整 bundle，回傳操作回執及新版本。前端只把已回執涵蓋的修改標為同步；較新輸入不能因舊回應抵達而被標成已儲存。

採強 ETag（HTTP 的精確資源版本標記）與 `If-Match` 作新接口的版本契約；版本不符返回 412，權限失效返回 403，認領或工作代號衝突返回 409。沿用舊接口的 SHA 欄位時，其含義必須等同精確 compare-and-swap；不得省略條件後重送。

### 5.2 同工看見的狀態

頁面持續顯示「尚待同步／儲存中／已儲存及時間／離線，修改保留於此裝置／儲存失敗／版本衝突」。訊息使用可被輔助技術讀取的 status 區域，不搶走編輯焦點。

瀏覽器以 IndexedDB 保存未確認送達的操作及基線版本，依登入身份與講道隔離。只存恢復所需文字與設定，不存影片、圖片或憑證。能寫入本機後才顯示「保留於此裝置」；容量或權限失敗時明確提示仍未持久保存。服務端儲存成功後清理對應操作；登出清理該身份的本機草稿前，對未同步內容提供匯出或返回編輯選擇。

斷線重連時先檢查登入、認領及版本，再恢復同一筆待存操作。版本已變則保留本機稿，顯示基線、本機及伺服器三方差異，由同工合併後再存；第一版不做無條件覆蓋或盲目全文自動合併。認領已轉交時只能匯出自己的待存內容，不能繼續寫入。

### 5.3 關頁與結果未知

換講道、切差異檢視、重新載入、發佈及取消認領，都先取消 debounce 等待、送出最新編輯並排空佇列。應用內切換若未同步成功，停留在當前稿件並保留文字。

瀏覽器關閉或系統中斷不能保證最後一筆網路寫入完成。因此即時保留本機待存操作，仍有未同步內容時使用離頁提醒；不能把 beforeunload 或 sendBeacon 當成可靠保存證明。

請求超時代表結果未知。先以 operation ID 查回執；有成功回執則接受該結果，確定未提交且版本仍一致才重送相同操作。恢復順序先核對回執，再判斷是否需要新的條件寫入；不能因自己的保存使版本前進，就把成功誤報為衝突。服務端對相同 ID 及相同負載返回原結果；相同 ID、不同負載拒絕。寫入前不靠重複 HTTP 請求產生重複紀錄。

### 5.4 可查看的編輯歷史

沿用頁面上既有「編輯歷史」入口，但新格式要顯示真正的稿件修訂，不只顯示現有 metadata 欄位變動。歷史列表提供版本、修改人、服務端時間、操作類型與變更摘要，可按文字、圖片、審核或工作流程篩選，並逐頁載入。

每次成功的自動儲存保存一個不可變 revision，包含該次合併提交的修改；不把每個按鍵都當成一筆歷史，也不能只有最後一份 current。口述、OCR、代表圖、閱讀位置、顯示／隱藏、審核確認及恢復操作都可比較前後差異。原圖不可變，更換代表圖時並排展示所選兩個原畫面；位置變動顯示原段落與新段落，不能只比較一長段 JSON。

認領、轉交、取消、採用候選及發佈形成另外的工作事件，與修訂按服務端時間顯示在同一歷史入口；事件保留原操作者，即使之後取消認領也不抹除。發佈事件連到它所發佈的確切 revision，不能只顯示當時最新、後來已改變的稿件。

有該稿可讀權限的同工可以查看歷史及唯讀版本，不能因此獲得編輯、恢復或查看原本無權存取稿件的權限。公開讀者不取得未發佈草稿與內部編輯歷史。

歷史恢復是新增選配，尚未由使用者決定保留；以下定義採用時的契約。只有當前認領人可執行「恢復為草稿」。恢復先同步自己的待存修改，再以預期 current 版本建立一個新 revision，記錄被恢復版本與恢復者；不改寫、刪除或截斷中間歷史。恢復的是內容與排版，不恢復舊認領人、不直接繼承舊人的確認或批准；恢復內容的核對狀態重新計算為待確認。公開版本不變，需再次核對及明確發佈才生效。

不可變修訂及來源資產納入既有資料備份，不能只備份 current 或以清理暫存刪除歷史。revision 除父版本 SHA、服務端時間與操作 ID，還保存服務端認證取得的 actor、變更類型、前後內容 SHA、變更對象及恢復來源；不能讓客戶端冒填審核者或修改歷史。首次採用保存 legacy 基線，已存在的 metadata audit 以原事件來源連結呈現，不杜撰過去沒有記錄的正文修改版本。

## 6 發佈與取消認領

### 6.1 發佈一個精確版本

發佈時暫停新的編輯輸入，先同步當前編輯器內容、所有待存操作及審核決定。若儲存失敗、發生版本衝突或未完成核對，保留草稿並定位問題，不繼續發佈。

服務端接收預期 bundle 版本、工作代號與發佈操作 ID，重新核對權限及審核內容 SHA。先持久保存該不可變 revision、圖片引用及編譯結果；確認檔案與雜湊完整後，才原子替換 `script_published/<item>.json`。此替換是公開版本生效的唯一提交點。暫停輸入只持續到本次發佈有確定結果；失敗時解除凍結並保留草稿。

發佈仍使用 `metadata/script` 容器。metadata 包含這個 revision 的標題／摘要等公開欄位，並新增 bundle revision、原始來源與視覺證據清單引用；script 是該 revision 的確定性圖文來源投影。口述與受控視覺區塊可被現有 `source_projection` 分別解析。新 public renderer 按 reading_layout 顯示代表圖與 OCR，不能把所有 SVG 當普通 Markdown 重複展示。已發佈講道的公開標題／簡介也取此快照，不被 SermonManager 的可變 metadata 覆蓋；新的草稿 metadata 不得提前出現在公開頁或目錄。

編譯時所有原始視覺事件都有清單與處置。納入正式視覺來源的內容綁精確圖像／OCR／SVG 與審核決定；未核實的內容保留於版本清單與閱讀提示，不偷偷升成文庫證據。投影改變則重新生成 locator 與 SHA 綁定，不能沿用之前 `Sxxxx/Vnn` 的批准。

公開檔、不可變 revision 與其投影必須能互相驗證。準備時崩潰則舊公開檔繼續有效；替換後崩潰則新公開檔有效。metadata 的 status、日期、歷史、目錄與通知是可重建投影，從發佈回執補齊；不能因後續更新失敗再回報成「未發佈」並盲目重做。

既有 `ScriptDelta.publish` 的鎖與原子替換可共用，但新格式需傳入同工確認的精確 revision；不得繼續使用 legacy 互動路由的「發佈當下碰巧讀到的稿件」。

### 6.2 與取消認領的關係

取消前先同步自己的修改。服務端比對工作代號，在同一工作流程鎖下釋放認領並保存操作回執。成功後頁面改為唯讀；不刪除草稿、已核對項目或已發佈檔。若有效公開版本存在，metadata 狀態維持 `published`。

發佈與取消是分開的兩次操作。同工發佈後仍可檢查完成版本，最後自行取消。取消成功前不顯示已釋放；結果未知時按操作回執核對。管理員已轉交後到達的舊分頁請求一律拒絕。

### 6.3 鎖與跨檔案一致性

新格式的認領、保存、發佈及取消都經同一服務層。固定先取得該講道工作流程鎖，再按需取得講道 metadata 檔案鎖；所有會改認領的既有入口也使用此順序。跨講道 metadata 更新需鎖內重讀並原子替換，防止保存整份列表覆蓋他人的認領。

所有需要兩把鎖的入口都按同一順序；禁止先拿 metadata 鎖再等待講道鎖。只改 metadata 的其他入口不得在持有該鎖時回頭呼叫工作命令。

內容／權限檢查與最後提交不能跨越認領變更。準備圖片、模型處理與其他長操作在鎖外完成，提交時重新驗證。操作回執必須隨權威資料一起持久保存：草稿操作在 bundle revision 中，認領操作在 metadata 更新中，發佈操作在 published metadata 中。文字審核不另引入 SQL 與檔案雙寫交易。

## 7 接口與程式接點

以下為目標契約，路徑尚未實作；實作可調整命名，不能改變條件、回執及權威資料的含義。

| 接口 | 契約 |
| --- | --- |
| `GET /sc_api/review_bundle/{item}` | 共用 resolver；JSON body 是 bundle 的確切表示，ETag 綁其 bytes；認領代號與權限沿用獨立 permissions 回應，不混入同一 ETag 的表示；仍檢查可讀權限 |
| `POST /sc_api/review_bundle/{item}/adopt` | 明確採用候選；帶原稿及候選 SHA，驗證無漂移及人工版本保護；建立 bundle 後不再寫 legacy review |
| `PATCH /sc_api/review_bundle/{item}` | 白名單操作，`If-Match`、工作代號及操作 ID；完整驗證後原子保存；確認動作也是這裡的操作 |
| `GET /sc_api/review_bundle/{item}/operations/{id}` | 核對本人的保存／發佈／認領結果；不可因知道 ID 而繞過 ACL |
| `GET /sc_api/review_bundle/{item}/history` | 受 ACL 保護的分頁歷史；整合已提交 revision 與工作事件，支援篩選及穩定事件 ID |
| `GET /sc_api/review_bundle/{item}/revisions/{revision}` | 唯讀檢視確切歷史版本及與另一版本的型別化差異；不載入孤立未提交 revision |
| `POST /sc_api/review_bundle/{item}/restore` | 選配，非既有功能；僅當前認領人；先排空修改，帶 If-Match、工作代號與操作 ID，建立新草稿 revision |
| 既有 `/assign` | 保留同工操作，新增工作代號、條件與回執；兩人認領及過期請求在服務端處理 |
| 既有 `/publish/{user_id}/{item}` | 保留入口或相容代理，身份由認證取得；新格式必須傳預期 revision 與操作 ID；讀回已發佈版本回執 |

前端沿用 `SurmonEditor`、SimpleMDE、播放器與編輯歷史；書籤、差異等小功能依第 12 節決定。移除 AI 問答面板、聊天狀態、問答請求及其專用引用 UI。把儲存佇列抽成共用控制器，讓文字與視覺修改一致處理；新增圖文審核卡片。移除 SlidePickerModal、工具列 insert-slide、人工截圖及 OCR 引文插入入口；保留舊 Markdown 圖片顯示及現有靜態資產服務。

後端由 SermonManager 統一 ACL 與工作命令，新增 bundle 儲存與 resolver；ScriptDelta 保留 legacy 行為，重用其可測試的檔案鎖／原子保存機制。新時間解析、公開讀取、metadata、目錄、來源解析與文庫取材都必須經明確版本適配，不能只改前端型別。

PATCH 的操作白名單至少覆蓋修改段落、修改指定 OCR 區域、選代表圖、指定閱讀段落、隱藏／還原及確認／提出疑問。來源影片 SHA、原始事件時間、審核者與回執不接受前端任意指定；asset ID 必須解析到該候選既有原圖。SVG 只由既有受控圖元產生器重建，不接受任意模型或使用者 HTML／SVG。

既有後端人工截圖等接口先不由本設計刪除，避免破壞其他使用者；完成依賴盤點後另行退役。移除 UI 不代表刪除歷史資產。

## 8 文庫消費與來源複核

本設計承接[視頻轉錄與文庫接入](./video_transcript_integration_v1.md)及[投影片文字與圖表證據抽取](./slide_visual_evidence_v1.md)。來源仍只登記為同一篇 sermon transcript；不得把 OCR 當另一篇獨立講道、把投影片字句冒充口述，或把排版位置冒充影片時間。

現有草稿加標題或來源補正入口對新格式必須寫入 bundle，再由同工發佈；不得經舊 helper 直接修改新格式 published 檔繞過此提交點。

發佈後，下游以發佈回執中的精確來源版本、視覺清單與審核紀錄建立取材包。不能在草稿自動儲存時抽取，更不能在未發佈新版時拿 current 覆蓋已用來源。再發佈應沿用既有來源修訂與依賴失效流程，不靜默改已生成 Claim 或文章的來源。

網站逐字稿發佈與文庫來源准入是兩件事。原圖可隨閱讀稿發佈；未核實 OCR、SVG 留在來源清單並明示，整個多模態包若仍有未處置項便標為未完整准入。可以明示只以已核對口述作部分取材，但不得宣稱已涵蓋全部投影片論證。

現有 `validate_visual_source_attestations` 要求每個視覺 locator 與 raw SVG SHA 的批准。不能把同工按一次逐字稿發佈，直接轉成「教授原始 SVG」的 attestation。正式視覺准入需擴充為「經核實的投影片重建」，保存原影格、裁切圖、OCR、SVG、人工確認與既有獨立來源複核的精確版本鏈。這個適配未完成前，既有拒絕規則保持有效。

本接入不重新引入第二次 ASR 重聽或重複辨識否決；已核對口述不因視覺來源准入失敗而被自動改回。

同工確認不取代 Claim／論證／CVP 的既有獨立 AI 複核；本工作也不套用 notes-to-sermon 的 manuscript 審核或 Fidelity Audit。

## 9 相容性與實作次序

1. **先修正共用工作流程。** 完成保存排空、互動發佈的預期版本、認領與發佈分離，以及取消不撤回公開版。先用 legacy 反例測試守住現有操作。
2. **增加 bundle 與適配器。** 完成採用候選、絕對毫秒、穩定身份、唯一草稿權威、原子版本與認領代號。先以一篇未人工修改的候選做測試資料，不寫 production。
3. **接入同工 UI。** 沿用既有編輯器，移除手動加圖，加入圖文審核卡片、段落確認、自動保存恢復及可理解的狀態提示。
4. **串通發佈與來源版本。** 驗證 reader renderer、Markdown／JSON 匯出、公開媒體定位、完整事件處置與後續文庫消費，再做完整認領到取消的演練。

以每篇講道是否具有已採用 bundle 選模式，先小範圍啟用。沒有 bundle 的講道繼續使用 legacy；新格式不得因關閉功能旗標就回退讀取舊稿。需要停用編輯時將新格式設唯讀，公開仍讀最後成功發佈版本。

原始 Markdown 中已有圖片照常可讀；不自動把歷史圖片當作已核實新 asset。已有人工稿的遷移需保留原 ID、時間及全部文字，以明確比對建立來源關係；第一版不自動全庫遷移。

## 10 驗收情境

| 情境 | 必須看見的結果 |
| --- | --- |
| 兩位同工同時認領 | 一人成功，另一人得到最新認領資訊；沒有第二名可寫入者 |
| 非認領同工或未接手的管理員提交修改 | 服務端拒絕；知道 API、版本或 operation ID 也無法繞過單人規則 |
| 同人兩分頁、管理員轉交、取消後重新認領 | 舊版本或舊工作代號拒絕；新人的稿件不被覆蓋 |
| 剛打完最後一字便按發佈 | 該字先保存並納入精確發佈版本；儲存失敗時不發佈 |
| legacy 非公開講道殘留歷史 published 檔 | 遷移與取消認領都不因檔案存在而重新公開 |
| 發佈後取消、已發佈講道再認領 | 公開仍是最後發佈版本；草稿變動不滲入公開閱讀與抽取 |
| 離線、恢復、關頁、重新登入 | 可恢復本機待存操作；未持久保存時不說已保留；他人身份不能讀到該草稿 |
| 保存已寫 revision 但尚未替換 current 就崩潰 | 不把孤立 revision 誤判為成功；原 current 仍是權威 |
| 確認段落後立即繼續輸入 | 新文字不能沿用剛才的舊確認；只使該段確認失效 |
| 服務端已保存但回應遺失 | 查操作回執可確認成功；不重複套用、不把已存資料當失敗丟棄 |
| 發佈準備或提交後程序崩潰 | 準備前後各有明確提交點；舊版或完整新版可讀，回執可修復 metadata 投影 |
| 長視頻及處理視窗接縫 | 新段落使用全片毫秒，後段沒有額外二十分鐘偏移；小數秒不因 API 保存而遺失 |
| 沒有 slide、教授遮擋、游標移動、重返舊頁 | 空白不補圖，遮擋不補字，游標不造新頁，返回事件仍獨立保留 |
| partial slide 含獨有論證、代表圖取自稍後 | 獨有內容有明確處置；閱讀位置與實際出現時間都可查 |
| 修改 OCR、圖片、位置或 SVG 字體 | 只使對應確認失效；原圖與口述不被改寫；舊 SHA 的批准不可套到新版 |
| 在保留的標題／摘要欄位修改內容 | 自動儲存於草稿，公開頁及目錄在再發佈前仍顯示舊快照 |
| 有疑問段落、未核實 OCR／SVG | 阻擋未解決的口述發佈；原圖閱讀可發佈，未核實視覺不得混成文庫已核實證據 |
| 查看歷史及差異 | 看到真實稿件修訂、操作者與時間；圖片／位置差異可理解，取消認領後歷史仍在 |
| 恢復舊版（若採用選配） | 新增版本，不刪中間歷史、不恢復舊認領或批准、不改公開版；舊版本衝突時拒絕 |
| 舊稿圖片、差異、書籤、metadata、加標題 | 舊功能可讀；新模式寫入走唯一權威，不丟欄位、不繞過版本條件 |
| 一條視覺證據進入文庫 | 能從論證回到該發佈版本、精確 OCR／圖元、原圖與影片時間；來源准入不成立時拒絕，不假裝成功 |

測試包括後端資料／競態反例、前端儲存佇列及瀏覽器完整演練。衡量同工完成一段所需時間、重複修改及恢復損失；不能只以播放成功或格式測試通過宣稱審核體驗完成。

## 11 設計選擇的依據

「認領、草稿與發佈分開」是針對現有單人校對、長時間編輯及穩定公開版本的選擇，不宣稱所有協作編輯器都應採同一模式。此場景不需要即時多人共同輸入或 CRDT（用於多人編輯的自動合併資料結構）；明確認領加版本衝突保護較容易操作與驗證。

條件寫入採 [RFC 9110 的 If-Match](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match)：以精確版本條件避免平行操作遺失更新。這支持寫入防護，不替本專案決定審核或發佈政策。

自動儲存狀態遵循 [W3C 對 Status Messages 的說明](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)：讓同工及輔助技術知道成功、等待或錯誤，不必打斷輸入焦點。自動儲存本身不保證不丟資料；本機恢復、操作回執及精確發佈一起構成保障。
