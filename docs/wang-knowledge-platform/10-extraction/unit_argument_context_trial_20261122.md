## 1. 从六讲中的同一份评测输入开始

`--unit-manifest` 接受按录音顺序排列的来源。每个来源提供原讲 ID、文件、文件 SHA-256 和一组有序、不重叠的闭区间。端点可以是原段号，也可以是现有生成器在整讲上产生的句号。原文按现有投影读取，保留原讲句号、段内字符位置和原段时码。清单只含要读的范围，不含分组答案。

以下命令在仓库根目录运行。第一个命令从来源复核盲测输入，同时在试验目录写一份可移机重建的清单。后两个命令分别对应这次通读与局部试验。`SOURCE_DIR` 指向三讲所在的已发布逐字稿目录，`RUN` 是已建好的独立试验目录，`CAPACITY` 是已有的共享模型容量配置。

```sh
export PYTHONPATH=.
backend/.venv/bin/python backend/pipeline/argument_golden/2012-nysc-matthew-3-parables/verify_blind.py \
  "$SOURCE_DIR" --write-unit-manifest "$RUN/manifest.json"
backend/.venv/bin/python -m backend.pipeline.claim_creation_flash \
  --unit-manifest "$RUN/manifest.json" --root "$RUN/reading" --capacity-file "$CAPACITY"
backend/.venv/bin/python -m backend.pipeline.claim_creation_flash \
  --source-id nysc-2012-3-6 --source-file "$SOURCE_DIR/2012 NYSC 專題：馬太福音釋經（三）6.json" \
  --grouped-package --steps-first --only-paragraphs S0003,S0012 \
  --unit-context "$RUN/reading/unit" --root "$RUN/sixth-test" --capacity-file "$CAPACITY"
```

单元通读只提出各次转题的第一句和留题位置。程序将相邻边界之间的全部句子分给对应组，回题时可以重用组名。超过模型输入预算则分批读取，后批仍可见先前的组与问题。局部抽取沿用既有 Claim、分步、分步记录、引经核对及逐句校验。通读材料只用来解释承接，局部候选的引文仍须落回它自己的原讲。

## 3. 本轮能判到哪里

简单题在一次真实的局部抽取中通过。长题可定位原始留题、分清终点的原因和目的，仍要在单元产物中检验「第五讲提出的马可平行段难题 → 第六讲新译如何解难 → 教授最后怎样综合」是否可追溯。通读得到的组名和问题属于生成线索，不能作为已验证的跨讲论证关系。本轮没有逐讲基线 A 的完整三讲候选，不能据此报告 A/B 改善幅度。
