## 2. 自审改变了哪些设计

| 最初想法经不起什么反例 | 已写进设计的修正 |
| --- | --- |
| 只增加一次跨组连线。首轮没有四 S0011 的开题节点，连线器找不到可连的对象。 | 让单元核对同时看问题原句与候选，区分漏节点和漏关系。前者回到对应组补抽，保留局部版本依赖。 |
| 只核对连接端点都存在。n14 与 n42 都真实，但边对理由的解释有错。 | 评测从总回答分别追原因、目的和条件，针对关系的作用逐条读原话。 |
| 为完整起见，把三讲并成一份 Claim 包。这样既混淆同号段落，也违背逐讲装载与 CVP 实例的约束。 | 本地 Claim 归原讲；单元候选引用带来源、版本的对象。将正式持久化留作待验证的独立契约。 |
| 要求每组都有主结论、每问都接到后来某项答案。原句可能只补论据，也可能尚未作答。 | 允许待接步骤与未答问题。若材料截止在四 S0011，评测期待留题；第五、第六讲进入后再检查实际承接。 |
| 把固定四单元或一次整包读完当作规则。独立插问会被吞掉，请求上限也会鼓励硬切同一论证。 | 用论题承接决定归属，完整原句决定证据；按请求分批时保持单元身份，另查原句覆盖。 |
| 把一份 PPT 当成现成的全套标准答案。简单题和部分语言细节需要回到教授自己的讲解。 | 同工材料只对照指定范围；两题各查逐字稿。原答已公开于本卡，另一个未见单元才适合做后续泛化验证。 |

```sh
  /opt/homebrew/var/www/church/web/data/script_published
```
