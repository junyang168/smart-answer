# 視頻轉錄與文庫接入 v1

> **讀者**：Developer、Solution architect
> **類型**：說明
> **狀態**：當前接入方案；格式橋接已實作，正式來源准入尚未接通
> **與代碼對齊**：未核對
> **權威範圍**：解釋接入位置與未完成項；不取代來源批准、Claim 或 CVP 的既有規則。

## 1. 接在既有流程的哪裡

視頻處理屬於逐字稿來源的上游，不直接產生文庫主張或文章。正式路徑是：

視頻 → 原聲轉錄／標點分段／投影片擷取 → 原聲加投影片提示校字 → 閱讀稿清理 → 對閱讀稿重新對齊 → 圖文來源候選 → 來源忠實複核 → 既有來源登記與主張抽取 → Claim／論證／CVP → 文章與問答。

[full_video_transcript.py](../../../backend/pipeline/full_video_transcript.py) 的 `run` 將準備、換頁、OCR、口述校對、閱讀稿、重新對齊、時間檢查與來源候選輸出串成一個可續跑入口。新視頻不依賴舊 pilot 或人工逐字稿。實體投影幕可加 `--projected-screen` 做透視裁切；完整原影格保留。已知講員可用 `--speaker-name` 傳入名字提示，它不代替原聲。未知付款結果不自動重送。

音訊按短視窗處理，但閱讀稿清理讀全片上下文；不能因例子跨越處理接縫，就把鋪陳當成閒聊刪掉。初次時間未解的段落先以相鄰聲學錨點圈定音訊再對齊，成功後補做該段第一次原聲校字，保留初稿與補處理紀錄，不用第二次 ASR 否決。重疊且未能修復的修改不套用；無法精確定位的刪除也保留原文。

現有講道編輯器的資料在 `script`、`script_patched`、`script_review`、`script_published`。新處理先輸出獨立候選，不能覆蓋這些目錄中的人工版本。後續「採用候選」需沿用現有版本衝突保護；不能改成背景覆寫。`sermon.json` 保留講道身份與進度，不塞入整份 OCR。

原轉錄系統的歷史批次入口未在本次改動中替換；[ImageToText](../../../backend/api/sc_api/image_to_text.py) 的人工截圖入口也仍存在。新增的 `run` 是來源處理入口，並不表示網頁已接上啟動工作、進度、取消及候選採用功能。

## 2. 同一份資料，兩種閱讀方式

| 用途 | 內容 | 位置關係 |
| --- | --- | --- |
| 讀者圖文稿 | 校對口述、投影片原圖、明示非口述的 OCR、圖表 SVG | 依原片絕對時間貼到重疊的完整段落；不切斷句子 |
| 文庫來源檔 | 同一口述、獨立視覺區塊、每區域與圖元的可解析身份 | 口述與視覺同篇取材，但用不同 modality 引用 |
| 稽核資料 | 原始 ASR、未刪校對稿、修改與刪除紀錄、時鐘檢查 | 不因閱讀稿刪去設備操作話語而刪掉原始證據 |

沒有投影片或畫面不明的時段是空白，不延用上一張。重複出現的投影片保留各自事件時間，OCR 可按圖片 SHA 共用。不以「同時出現」推定教授贊同或已口述某句。

## 3. 如何插入，且讓現有抽取器讀懂

[video_transcript_handoff.py](../../../backend/pipeline/video_transcript_handoff.py) 輸出 `handoff/<講道 ID>.json`，採用既有 `metadata`／`script` 容器，段落帶原片秒數。口述不混入 OCR 句子；視覺區塊用受控 SVG 文字與圖元表達。純文字投影片只產生文字元素，不被標成 diagram，也不憑空加箭頭。

這裡的 SVG 是辨識結果的表示格式，不是教授留下的原始 SVG。原投影片圖片、圖片 SHA、內容 SHA、畫面與擷取時間、OCR 不確定區域，以及出現事件均另綁於 `extraction_handoff.json`。沒有對應口述的投影片保存為純視覺來源，不丟棄。

現有 [source_projection.py](../../../backend/pipeline/source_projection.py) 會從這份候選建立 `Sxxxx/Vnn` 視覺單位及 literal facts，並將視覺內容排除於口述投影。既有 [detailed_knowledge_extraction_runner.py](../../../backend/pipeline/detailed_knowledge_extraction_runner.py) 已有多模態輸入、`source_modality=visual` 與 `visual_fact_ids`；不必新造第二條 Claim 流程。

文字不只給校字用，也需作為論證取材。下游應能表達「教授在口述提出判斷，並以這張圖／譯文對照說明」；視覺箭頭本身只證明可見連接，不能自動變成因果或神學結論。抽取須核對全部視覺單位的處置，不能只看已產生的 Claim 判定沒有遺漏。

## 4. 正式接入仍缺哪一段

目前完成的是格式橋接，不是來源批准。候選明示 `machine_candidate`、零 SQL 寫入、空 `visual_source_attestations`；既有抽取器會拒絕未批准的視覺來源。不能因 XML 可解析，便把模型重繪套成「教授顯示的原始 SVG」批准。

正式准入還需接上：

1. 讓來源複核同時讀原影格、裁切圖、OCR／SVG 和相鄰口述，保存圖片到重繪的派生鏈。按照[既有架構](../00-overview/solution_architecture.md)使用不同供應商獨立複核及有界修正，不能只比較 OCR 字串是否相同。
2. 擴展既有視覺來源准入，明確接收「已核實的投影片重建」及其精確圖片／區域／SVG SHA，而非假稱教授原始 SVG。未決區域保留並披露，不能補成確定文字。
3. 通過既有來源版本與登記流程後，以同一來源檔進入現有主張抽取；驗證真實主張及證據步驟能引用視覺來源、原圖和原片時間。修改來源時沿用來源修訂流程，不靜默改已用來源。

接入驗收需包含：無 slide、教授遮擋、游標移動、逐步顯示、返回舊頁、多語原文、晚段時間、人工版本保護，以及一條真實視覺證據穿過主張與論證層的案例。格式回歸測試通過不能代替最後一項，也不能宣稱文章已使用這批投影片。
