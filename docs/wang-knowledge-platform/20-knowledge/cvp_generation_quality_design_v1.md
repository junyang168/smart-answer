# CVP 生成质量评估设计 v1

> **读者**：Solution architect、Developer、内容审核同工。
> **类型**：规范。
> **状态**：当前；#429 的评估设计，尚未实现或实际运行。
> **与代码对齐**：未核对；本文定义验收契约，不宣称已有独立评估入口。
> **权威范围**：CVP 生成质量评估的范围、样本、指标、证据与报告；不授予知识库修改、额外生产重审或发布权限。受 [Project Mission Statement](../00-overview/project_mission_statement.md)、[Solution Architecture](../00-overview/solution_architecture.md) 和 [CanonicalViewpoint 设计](./canonical_viewpoint_design.md) 约束。

## 1. 目的与边界

回答的是：生成的观点能否忠实、完整地整理教授的教导，跨讲道归并是否正确。不是评价教授神学是否正确，也不是检验文字是否符合外部神学体系。

生产结案、机械检查通过、内容质量评估完成是三个不同事实。生产组全部结案不证明没有遗漏、重复或系统性错误；本评估也不自动推翻原批准、洗掉异议或取得写入权限。既有 [文库独立审计](../90-ops/library-audit/README.md) 是证据来源与可复用基础，不因已有审计就省略本设计的抽样和双向检查。

本卡只读当前 SQL、物理原文和精确历史证据，独立保存评估材料。不重启完成的生产 campaign，不生成新 Claim／CVP，不启 ArgumentRoute、文章、发布、部署、migration 或 admission。Evidence 接入功能的生产验收是另一任务，不是本评估的前置内容修改。

## 2. 基线与评估单位

执行前保存版本化评估计划：范围及排除理由、当前 CVP／CVR／Claim／link ID 与版本／内容 SHA、完整依赖集合、来源身份／路径／物理 SHA、读取时间、代码与模型配置。程序计算 SHA，不让模型抄写。开始与收尾核对相关版本；漂移只使受影响单元过期，不拼接两代材料得出当前结论。

区分三个分母：

| 评估单位 | 回答的问题 | 必需材料 |
| --- | --- | --- |
| 当前观点 | 命题、范围、所有成员是否一致；粒度是否合适 | 当前完整 CVR、所有有效身份成员与关联连接、各自 Evidence／fragment、每份自身来源完整正文、必要关系端点 |
| 当前连接 | 该 Claim 成分是否具有声称的作用 | 精确 Claim／CVR、type／locator／Evidence、完整自身正文；不能只读摘要 |
| 完整来源 | 教授讲出的重要判断有没有被知识库遗漏或错误拆分 | 完整物理正文及编辑文字标识；之后才对照本源 Claim、disposition 与相连当前 CVP |

生产原组数量、原 Claim 数、Registry 当前观点数不可互换。一个观点多个连接不重复算多个观点；来源 aliases、编辑视图和同源修订不重复算独立讲道。外部关联成员即使不属原生产分母，也必须完整进入被选观点的材料。

## 3. 双向评估与质量维度

每个适用维度给出 `adequate`（证据充分）、`defect`（具体缺陷）、`uncertain`（材料完整但仍不确定）或 `not_assessable`（缺材料／拒答／运行失败）。不以总分抵消任何维度的实质缺陷。

| 维度 | 必须回答 | 典型缺陷 |
| --- | --- | --- |
| 原文忠实度与归属 | 观点的每个独立谓词是否来自教授；编辑归一化是否明示 | 新增原文未讲判断、把反方／编辑文字算为教授主张 |
| 限定与范围 | 对象、否定、条件、因果、模态、人群与时段是否保留 | 把局部结论普遍化、漏条件、将证据经文列表误作适用限制 |
| 身份归并 | 所有身份成员在教授自身语境中是否表达同一判断 | over-merge、把相容／同主题／支持误算等价 |
| 观点粒度与重复 | 独立命题是否错误拼成一条；同义判断是否被拆成多条 | 过粗、过碎、跨批重复；正反表述不能仅凭形式判重复 |
| 连接角色 | 成分是否实际发挥该 type 的作用，定位和依据是否正确 | 因果方向倒置、应用冒充论据、限定被误问为身份等价 |
| 来源到观点覆盖 | 原文里的重要判断及限定是否有明确去向 | Claim 抽取遗漏、Claim 正确却无观点覆盖、不同讲道补充被遗漏 |

正向从观点读回各成员原文。反向先读完整来源，独立列出需核对的教学判断及逐字位置，再看知识库。反向清单只是评估观察，不是新 Claim 或教授思想的“黄金记录”；不同措辞须按语境对齐，不按字符串匹配宣称缺漏。

`supports` 只需有具体论证作用，不必独自证明整个 CVP；`qualifies`、`extends`、`applies` 等按完整角色定义判断，不拿“不是等价”证明它们错误。同一 Claim 的结论与论据成分可分别发挥作用，必须区分唯一 Claim 数和连接数。自身语境可解释明确指代、省略及正反表述，不能补进另一项独立结论。

严重程度独立于缺陷类型：`critical` 为误署来源／新增教导／改变核心真值条件，`major` 为实质限定、成员或论证作用错误，`minor` 为不改变教导含义的表达问题。材料缺失和模型失败列为评估限制，不虚报内容缺陷或 pass。

## 4. 全量筛查与分层抽样

全量只读结构盘点检查引用、版本、角色、成员及来源可解析性，并产生语义风险候选；相似措辞、共同经文、成员多寡不能直接成为合并或缺陷结论。跨观点比较属于评估，不重建生产的 blocking／候选配对身份决策流程。

随机样本与定向风险样本分开冻结。随机部分按可从当前记录与 provenance 证明的来源类型、单源／跨源、成员规模分层；生成 profile／scope 修订／merge／人工保留等作为覆盖标签。风险部分覆盖疑似重复／过宽／过碎、多成分角色及历史异议。标签未知就列 unknown，不为补齐类别猜测。来源反向检查另有独立来源抽样框，不能只选被 CVP 使用的来源而漏掉没有连接的来源。

冻结计划必须写出每层母体大小、抽取数、无放回规则、确定性种子、稳定排序、入选概率、风险选择理由和预算。样本数量由期望识别的缺陷水平与可用完整材料决定，先写理由再选样；不得看结果后缩样、换掉拒答或追加“漂亮样本”。稀少层可全查，注明 census；扩样使用单独版本及理由，保留原结果。

已知耗尽争议、人工精确保留和安全拒答仍留在抽样框；可计入证据复用或受限单元，不能悄悄排除。没有合法新调用预算时，不再请求该同题语义判读，并在报告注明它不属于新的盲评证据。

## 5. 独立性、历史证据与调用边界

独立评估须有自己的读取／校验路径，不 import 生产 `backend/` 读取器或内容模型；直接打开物理原件；语义判断使用未参与原生成判定的模型。初评不展示原 pass／reject／理由、人工结论和生产进度，仍提供完整当前内容、角色定义、归属、所有成员和完整来源。不能为了盲评删掉语义所需上下文。

历史复核阶段才展示精确原生成上下文、审核理由及人工决定，分别保存盲评与复核结果、差异和证据。历史批准不是质量无误的证据；新的局部拒绝也不是自动推翻既有上下文判断的权力。已有裁决精确绑定的同题不再仲裁；无法证明同一问题时保存差异，不挑有利答案、不改旧 reject／upheld／disputed。

模型、backend、effort、prompt／schema、实际材料与 request bytes、单项／总调用数及恢复规则须在新评估计划中显式固定。当前任务只更新设计，不启动模型。后续新调用必须同时满足执行授权及原同题预算边界；#429、新 root 或换名称不产生第二份裁决预算。

完整输入过大时先采用经验证的无损编码；按 CVP／完整来源单元安排评估，但不得把某观点的成员截断。仍超限就记受限，不以删原文、漏成员或自动提高预算过关。intent 无答案为 unknown，不自动重发；安全拒答不通过换模型／缩文绕过。GPT 6.1 Sol high 原文补判若参与过生成，只能标补充证据，不称独立通过。原 revisit／independent flags 与人工保留原样披露。

## 6. 报告与验收

报告逐维度给出适用数、已实际评估数、缺陷数、未决数与受限数；缺陷率分母必须明示。随机样本估计使用实际入选概率及合适的区间方法，记录计算方法／实现版本；风险样本只报检出结果，不外推全库。受限／未决不是随机缺失，必须披露其比例及对结论的影响，不能只对愿意回答的样本算“全库质量”。重复／漏记的发现率不能冒充完整召回率。模型异议率和经证据核查的缺陷率分列，不把前者叫“准确率”。

每条 finding 绑定 exact IDs／版本、维度、逐字位置、具体语义差异、严重程度、判断身份及历史处置；记录最早可证明原因是来源、抽取、Evidence、身份归并、CVR 表述／scope、连接角色或审核输入／工程问题。不能为让当前连接成立而先改 Claim。

交付基线／计划、双向完整样本结果、历史复核差异、可复现指标、受限与未评估范围、系统性问题和最小修复建议。固定样本全部有结果或明确受限记录，证据与当前版本验证通过，才称“本轮评估完成”；有严重缺陷仍可完成报告，但不得称“质量合格”。无代表性证据或重要维度未评估时不能给出全库质量通过结论。

如需作“质量合格”决定，计划还须在看到结果前声明各维度的验收标准、严重缺陷处置及受限比例允许范围；没有这些标准时只交付质量基线与证据，不临时设一个总分或零异议门槛。不得把抽样未发现缺陷写成全库无缺陷。

评估 findings 不改变生产完成记录、批准、复审 flags 或知识库。修复另卡进入相应 Claim／CVP management，必须有权限、完整后像审核、共同 SQL、回读、受影响完整审计及完成证明。流程见 [CVP 生成质量评估流程 v1](./cvp_generation_quality_workflow_v1.md)。
