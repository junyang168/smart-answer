# CVP 生成质量评估流程 v1

> **读者**：Developer、评估执行者、内容审核同工。
> **类型**：流程。
> **状态**：当前；#429 设计阶段，未启动实际评估。
> **与代码对齐**：未核对；阶段和文件名是待实现契约，不是已存在 CLI。
> **权威范围**：独立质量评估的执行次序、输入、产物和退出条件；质量定义见 [CVP 生成质量评估设计 v1](./cvp_generation_quality_design_v1.md)。不取代生产或修复流程。

## 1. 建立独立评估范围

先读 mission、architecture、CanonicalViewpoint 设计、质量设计与文档约定，在本卡独立 worktree 工作，primary 只读。不复用 #357 输出目录、后台进程或生产工作树，不恢复已完成 campaign。

执行者先核实当前生产进程、实际 worker lock、SQL 完成与当前物件版本。只读评估不取得生产写入资格；若有写入进行中，等待稳定基线或明确评估历史切面，不把中途两代记录混成当前状态。需要锁时仅按现有真实锁契约使用非阻塞方式，不能另造一把锁假装已排他。

只更新设计文档时无需启动生产 worker、模型或创建 SQL 评估记录。本卡与 [#357](https://github.com/junyang168/smart-answer/issues/357)／[#428](https://github.com/junyang168/smart-answer/pull/428) 的代码／文档合并依赖要单列；未合并的现行交易和管理实现不能写成 main 已有功能，也不把整个生产分支并入本卡。

## 2. 冻结只读基线

按 explicit scope 读取当前 active CVP/CVR、全部有效 links、Claims／Evidence／fragments、必要关系端点与来源 metadata；声明历史 redirected／merged／retired 对象只作证明，不混入 active 分母。来源反向抽样使用已声明 corpus，包含没有 CVP 的合格来源。

独立读取器直接验证物理文件、正文与逐字位置、编辑标题／删除线标识；不信存储的 anchor_state 作为结果。输出完整 ID／revision／SHA 清单和来源身份去重依据，不解析历史整库 before／frozen／readback 或递归祖先链。

产出 `baseline.json`：scope、相关版本 pins、源 SHA、对象／来源分母、读取时间和排除项。程序验证读取一致性；缺来源、真实 hold 或证明冲突显式列出，不能为能跑模型而隐去。

## 3. 先定指标与样本，再看结果

产出 `evaluation-plan.json`：六个质量维度、严重程度、随机分层母体／抽取数／理由／种子／排序／入选概率、另列风险样本、完整来源样本、角色契约、模型配置和单项／总预算、历史裁决碰撞规则与报告统计方法。

运行结构筛查仅生成风险标记，保留全母体和所有选择理由。冻结 `sample-manifest.json`，样本不能因拒答、困难或不利结果被替换；同一 CVP 入选多个标签只评一次，并记录所有标签。普通随机结果和风险检出结果分别计算。

先验证程序反例：样本可复现、漏成员／外来 ID／错版拒绝、语义角色不误问、全文无截断、物理 SHA 漂移拒绝、旧 raw 不升级、同题预算不重置、unknown 不重发。合成评估回答只是测试 fixture，不是教授内容批准。

实施验证须走完整评估链：基线 → 样本 → 正反向组包 → 新／保存／受限回答 → 历史复核 → 统计 → 收尾版本检查 → 报告验收。覆盖无成员、跨源、多角色、人工保留、拒答、unknown、漂移及中断恢复；确认没有 Registry／生产状态写入。不能以一个组包函数或局部 fixture 通过冒充整轮实际评估。

## 4. 组包与同题预算检查

正向包提供当前 CVR 全命题／signature／scope、所有成员和连接、精确成分及自有 Evidence、完整各自身正文；只送任务所需的版本化角色规则，不发送整份架构／设计文档。

反向第一包只提供完整来源、编辑标识及观察契约，独立列出原文判断及位置；第二包将观察与本源实际 Claim／disposition、相连 CVP 及完整必要成员对照。第一包观察和第二包结果分开保存，不把观察作为新 Claim 写库。

程序先只读检查历史实际 request／raw／裁决／intent 与人工方向，避免向模型泄露结论。精确已有同题裁决以原身份复用并标 `historical_evidence`，不是新的盲评；耗尽／unknown／被保护项记 `restricted`，保留在样本分母。未发现同题也不默认获准调用，仍须核对冻结执行计划。

每个合法新评估阶段在调用前持久保存实际 material、配置、编码、请求字节和 once intent。允许保存新评估证据，不改原生产 metadata、raw、预算或独立复审 flags。尚未实现这些边界时只做零调用预检，不提供貌似可运行的新命令。

## 5. 独立初评与历史复核

独立初评沿独立读取／物理原件／不同模型三条边界执行，不展示原模型 pass／reject／理由或人工结果。模型逐维度给出证据和明确的结果类型，自己的代码验证 ID、完整分母、位置、角色及实际 raw，不从理由推测或重映射 ID。

再对初评疑点和受限项读取原生成材料、完整上下文、审核理由与现有人工决定，生成 `context-review.json`。确认是不是指代／口语省略、实际新增谓词／条件、Evidence 问题、角色定义漏包或原始转录问题；记录初评与复核的变化，不覆盖初评。

本流程不新开生产 correction／final round，不因初评拒绝反复问到 pass。可精确复用的原裁决只解释证据状态；真正新的内容问题保存报告，常规工程输入缺陷先查根因。额外模型输入修复须有合法固定父 once 契约，不能凭写了代码取得新预算。无法消解的内容问题才交最小人工包，不逐项询问工程步骤许可。

## 6. 收口与报告

独立保存 `findings.json`：每条 exact 对象／版本／源、质量维度、严重程度、原文证据、实质误读、最早可证明根因、原判定与当前复核、建议处理域。相同缺陷跨样本出现时关联同一问题，不能重复算多次缺陷却不披露计数单位。

产出 `quality-report.md`／`metrics.json`：基线、设计与实际样本、每维度随机估计及方法／区间、风险检出、反向覆盖观察、系统性模式、未决／受限／未评估范围、调用与人工成本。量化结果由原始逐项记录计算，不让模型手填通过率。

收尾重新核对所有相关 SQL pins 和物理来源；漂移项保留原切面结果且标 stale，不自动补跑。检查全样本都有完整结果或受限理由、历史与新证据身份正确、无生产对象／checkpoint／审批写入。生成 `evaluation-acceptance.json`，只表示本轮报告与证据完整，不是质量 pass 或生产批准。

含教授原文的包、raw、报告及受限证明放在独立 staging，并按既有 SSD／归档规则保存；Git 只收流程、代码和不含原文的记录。恢复读取精确阶段和已保存回答，禁止冷启动重复评估、删失败、重置 intent 或另起 root 获得预算。

## 7. 修复交接与完成声明

finding 分流到来源校对、Claim／Evidence management、CVP 表述／身份／连接 management 或工程输入修复。修复卡包含版本／证据／最小权限与受影响范围；质量评估报告不能代替 GPT 提议、独立 Opus 后像批准、共同 SQL transaction、SSD backup、current／history 回读及完整受影响审计。

既有三类事实原样保留：实际 provider 判断、精确人工决定、非独立安全补判。报告不声称人工保留是模型一致，不以补判解除 independent incomplete，不把候选内部关系当批准。

“设计完成”“程序验证完成”“实际样本评估完成”“缺陷修复完成”分别汇报。#429 只有本轮真实评估交付满足设计验收才可结案；文档提交／PR 合并不能冒充测试完成。#357 生产完成不被本卡自动重开，#428 不因本卡开出或设计通过而自动合并。
