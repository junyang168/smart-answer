# Draft-first 文章流程 v1

> **读者**：神学编辑、Solution architect、Developer
> **类型**：流程
> **状态**：当前
> **与代码对齐**：未核对（2026-09-10 的 Matthew adapter 尚未实作）
> **权威范围**：draft-first 生产线从输入到负责人终审的运行阶段、各道检查的职责边界、修订循环与停止规则。写作规则的具体条文以 prompt 文件为准；知识层（观点、论证路线）的形成不在本文范围。

## 一、这是什么

Draft-first 是专题综合文章唯一的当前生产线；2026-09-10，负责人也把它定为马太释经的新生产线。旧 Brief 管线和马太 `CompositionPlan` 入口已经退役；历史成品和审稿记录继续只读保留。马太的 passage-specific adapter 尚未实作，在它通过验证以前不得退回旧 runner 继续生产。它的做法一句话说完：

> **先放手写好，再逐句查实。**

写的机器拿到三样东西——要回答的问题、已批准的观点清单、可查阅的教授原文——写出全文。材料较少时直接交付全文；跨多篇来源时采用第三节的分步阅读，不要求全库原文同时进入一次上下文。写完之后，四道独立的检查逐句核对：说的是不是教授的意思、读者能不能收到答案、文章配不配称为完成。查出问题就退回修改，最多改两轮；两轮修不干净就停下来交给人。

这条线的设计信条来自实测：**好文章靠好作者读完整材料写出来，忠实靠事后检查保证，不靠事前的条条框框。** 规矩越堆越多的老路（一个缺陷加一条规则）已被证明会把文章勒成合规清单。

## 三、每一步说清楚

### 输入：三样东西，由共享编译器从权威数据产生

没有任何一样需要为写文章新造。读者问题由编辑一句话给出；独立的 `theological_evidence_packet_runner` 从当前 master data 机械编译已批准的观点、论证路线、Claims、来源片段和完整逐字稿／母本，并把依赖与内容 SHA 锁进同一个 `TheologicalEvidencePacket`。作者只读这份 packet，不直接遍历 registry。**观点清单里那份「留而未决的关系」必须随清单同行**——写的和查的都要拿到它，否则文章会把教授没说定的事写成定论（真实发生过一次，四道检查全员漏放，教训换来的规矩）。

### 分步阅读：原文完整保存，按需要查阅

编包入口的 `--source-delivery source_library` 将全部相关原文及其 SHA 保存在材料包中，
不把整批正文直接发送给模型。作者、对齐检查、编辑审稿、修订与来源绑定均通过
`draft_first_source_reader` 先查看完整观点清单、条件、范围、已审核关系、来源目录及证据位置，
再请求指定来源的完整编号块；可以继续读取相邻块或其他来源。阅读笔记不是证据或新的批准。
实际读取、选择保留的原文及最终任务的精确输入、原始回复均保存，可重新核对。

每阶段至多十轮读取，保留与单次请求的原文上限为 55,000 字符，完整请求上限为
450,000 UTF-8 字节。超限、未知来源、越界位置、保留未读块或预算耗尽都停止，不能截断。
完整语料分母保留在材料包中；模型只读过部分材料不等于全主题无遗漏，仍须对照主题覆盖清单。
阅读轮不生成编辑评分；初稿仍只有一次独立编辑审稿，修订后每轮仍只有一次 delta 判断。

读取中断后只复用输入完全一致、且与原始 provider 回复相符的已保存结果；失败请求至多恢复一次，
不重置阅读轮数。对齐检查的 provider 不可用时，盲读与独立编辑仍可完成，作者可处理已确认的正文问题；
缺失检查保持未完成，不能当作通过。若没有可修的正文问题而 provider 仍不可用，状态为 `provider_hold`。
若两轮后仍有正文问题则为 `human_review_required`，同时保留 provider 错误；两种状态都不允许发布。
如果首次对齐没有完成，后续恢复时必须先完成全文对齐，不能假定未改段落已经通过。

当前已批准观点也可由编辑按负责人确定的读者问题直接选择：`--editorial-selection` 指定文章本地清单，
清单中的 `selection_id` 与 scope 的 `structure_revision_id` 一致，并记录 `attribution=church_editor`
和 `decision_basis`。它不批准新的知识结构，不写 Registry，也不继承旧结构的过期观点引用。
每个被选观点仍须为当前已批准版本；全部实际知识依赖继续按 SHA 绑定。旧有结构入口继续可用。

未完成当前版本路线整理的观点会列出编包警告；不能因此声称教授没有论证，也不得用旧版路线
冒充当前批准。若正文展开该处原文，审稿必须实际查阅对应论证，不得凭不存在的路线作出验证结论。

### 写稿的文字要求

写的机器充分阅读所用论证的原文与必要上下文再动笔。规则是功能性的，不规定结构：一个问题发动全文、结尾落一次答案、断言不越观点清单、引文逐字、教授的生动讲法优先采用但导言克制、枝蔓修剪、编辑观察只进编者注；正文以编者口吻直接讲解，不以「教授说」「讲某书时他说」逐段标注出处——出处由来源绑定承担。全文只在第一次逐字引用时点名教授，此后用「他」或把引语织进句子；「他」可能被读成耶稣时不用。这条同时写进作者、修订、对齐与编审四份 prompt；程序另查正文里的后台用语（材料、母本、本文、各自站立等）、逐段出处标注，以及正文点名教授超过两次，与引文核对一样列为 blocking。原先的写法「引语前交代一次说话人，同段不重复」被读成每段可点名一次，人子一篇第三稿因此出现九处「王教授说」。观点清单每条带教授的观察依据（`observation_supports`：他在经文用词、冠词、语法、译文上看到什么、支持观点的哪一部分、范围多大）与 subject／predicate／object；没有推理路线的观点仍按观察写，不夸大成逐例证明。`polarity` 是命题本身的正负，已写进核心命题，对齐检查不再叠加一次否定——「中文沒有辦法翻」曾因此被误报。编审回答违反输出契约（如 anchor 不是逐字）时重试一次；被拒的回答单独保存，不计为审稿，每轮仍只有一次被采纳的编审。论证骨架按路线走——保证文章与问答等其他产品对同一论证说法一致——但路线不设细节上限，血肉照旧从原文取。没有完整路线的观点（人子一篇 17 条里有 8 条，包括中心主张）在观点清单里标明，论证顺序跟随一篇讲道自己的讲法，不把不同讲道的步骤串起来。清单里每条观点都要落地，一句话带过不算；观点的限定条件是边界，不写成原文没说过的断言。篇幅不设目标（负责人，2026-10-22：言之有物，不是越长越好，也不是越短越好）。读者是神学生和追求的基督徒，作者、编审、盲读三处同一画像。

### 四道检查：各管一件事，互不代劳

| 检查 | 拿到什么 | 回答什么 |
|---|---|---|
| 引文核对 | 成稿 + 原文 + 和合本 | 引号里的字是不是一字不差（程序比对，不经模型）。经文引文块也可对和合本：文章据以论证的经文必须完整摆出，教授常只报出处不念全文（約5:27、太9:6），所以程序取来源提到的各章和合本作第二依据，逐章记 SHA；标点不计，字须一字不差。行内引号里是教授的话，只对讲道 |
| 逐句对材料 | 成稿 + 观点清单 + 未决清单 + 原文 | 每句话有没有说过头：清单否定的立场被正面断言、「更可能」被说死、未决的关系被合并、材料的沉默被说成经文的沉默、原文没有的事实被补出来 |
| 盲读测试 | **只有成稿** | 一个不知情的读者读完，能不能用一句话说出正确答案、保住该保的限定。故意用最小的模型——它就是普通读者的替身 |
| 编辑审稿 | 成稿 + 观点清单 + 路线 + 原文 + 质量维度表 | 该写的写全没有、论证每一步是不是教授在同一篇讲道里真走过（对照每来源的见证步骤）、有血肉但不过分的度、每个维度过没过自己的最低线 |

写的和查的**永远不是同一个模型**；查忠实度的与写的还隔着厂牌。

### 修订循环：改动的地方重查，其余不折腾

必须修的问题汇总退回写的机器，按条最小修改，不许顺手润色别处。复查只看改动的段落加**全文结尾**（结尾无论改没改每轮都重读——插进新段落时，没动过的收束段不在改动清单里，但它仍是读者读到的最后一句）。没被本轮问题触及的维度分数由程序原样继承，不重新掷骰。最多两轮；仍有问题就停下、写明原因、交给人——**机器永远不硬发**。

### 来源绑定与登记：给审稿的人配全证据

绑定回答「这段话教授在哪里说过」：每段标出原文逐字片段，程序逐字核实，对不上的一律丢弃并记录（第一次实跑就丢弃过全部 37 条错误提案，零错误进页面）。讲道出处自动带录音跳转；论证段另附教授这条论证的步骤展开。稿件、检查记录、绑定、材料包四者的内容指纹互锁登记——事后改动任何一份，审稿页立刻显示「已改变」。

### 负责人终审：流程里唯一的人工点

审稿页上逐段看原话、听录音、走论证。发布键只有人能按。材料不足时文章宁可少一句应用也不编造（平台既有裁决）；同理，检查修不干净时宁可停下也不放行。

## 四、规矩从哪里来

写作规则不是设计出来的，是**裁决累积出来的**：负责人每一次具体的编辑意见（「细节过多」「编辑观察入注」「结尾稍有重复」）被泛化成一条与具体文章无关的规则，进入规则文件，四道检查同步引用同一条界线——规矩只让一个环节知道，迟早会被别的环节改掉，这是平台反复付过学费的教训。外部复查（另一家模型的审计）同样走这条路：发现 → 验证 → 规则或代码 → 全线生效。

## 五、Brief 与马太 CompositionPlan 入口已经退役

专题综合文章不再生成 Brief，也不再调用旧的「按 Brief 撰写 → Grounding／Program Audit」半套。历史 Brief 版文章、审核 artifact 和审稿页渲染继续只读可见；它们不是新生产入口。证据包编译器是知识层与文章层之间的共享地基，已从旧 Composition runner 独立出来。

2026-09-10，负责人进一步退役马太释经的 `CompositionPlan` 入口；马太新稿也必须采用 draft-first 的「先写、后核」边界。现有专题命令不能冒充 passage adapter，旧 Matthew runner 也不能在迁移完成前作为 fallback。该决定未改变微讲道流程。

## 六、Developer 附录

以下是当前已实作的**专题文章 adapter** 命令（全部模型调用走订阅 CLI，不直连 API）。它们不构成马太释经的可运行入口；马太 adapter 完成前不得用旧 `--plan-id` 命令替代：

```bash
# 先从当前 master data 编译 SHA-bound packet（不会调用模型）
backend/.venv/bin/python -m backend.pipeline.theological_evidence_packet_runner \
  --scope <scope.json> --output-dir <run>/packet

# 只验证编包输入与输出；仍写出 packet 供检查
backend/.venv/bin/python -m backend.pipeline.theological_evidence_packet_runner \
  --scope <scope.json> --output-dir <run>/packet-dry-run --dry-run

# 写稿
backend/.venv/bin/python -m backend.pipeline.draft_first_author_runner \
  --packet <run>/packet/theological-evidence-packet.json --reader-question "<一句话>" \
  --output-dir <run>/author-v1

# 四道检查 + 修订循环
backend/.venv/bin/python -m backend.pipeline.draft_first_review_runner \
  --draft <run>/author-v1/draft.md --packet <同上> --output-dir <run>/review-v1

# 来源绑定
backend/.venv/bin/python -m backend.pipeline.draft_first_source_binding \
  --draft <run>/review-v1/final.md --packet <同上> \
  --output <run>/review-v1/source-bindings.json

# 登记进审稿页
backend/.venv/bin/python scripts/register-draft-first-review.py \
  --review-id <id> --passage "<经文>" --review-dir <run>/review-v1 \
  --bindings <run>/review-v1/source-bindings.json --packet <同上>
```

模型分工：写稿与修订 `claude-opus-5`；逐句对材料与盲读比对 `gpt-5.6-sol`（codex CLI）；盲读 `claude-haiku-4-5`；编辑审稿 `claude-fable-5`。写作规则在 `backend/pipeline/prompts/draft_first_topic_author.md`，四道检查的判准各在同目录的 `draft_first_*` prompt。质量维度表沿用 `WQ-theological-topic-essay-v1`。每次检查调用的 prompt、输入、输出三重内容指纹记录于 `review-run.json`。
