# 聆聽投影片的論證圖

> **讀者**：神學編輯、Developer。
> **類型**：規範。
> **狀態**：當前。
> **與代碼對齊**：2026-11-18（核對到 `1cf3a562`）。
> **權威範圍**：論證圖如何進入聆聽投影片，以及發布前的驗收條件。

## 1. 目標

聽眾在教授講到一條論點時看到相應的圖。圖隨論證層更新，播放時間取自已校對的原文。出版時連同對應的聆聽單元與章摘要一起驗收。

## 2. 選圖與署名

- 出版流程從論證庫讀目前有效的 Claim、指向它的 `supports` 連接、Observation、視覺 SourceFragment 和來源文件。圖在別講或母本時也按這條連接選入。獨立論證 Eval 的 golden keys 不參與選圖。
- 視覺片段需通過 SVG 安全校驗，完整圖檔須符合資料庫所存的 SHA-256。作者類型取自同一個片段的來源證明。來源名稱和類型供內部核對，聆聽畫面只呈現圖。缺少或互相矛盾的作者證明時，該圖不進投影片。
- A「宗主國與附庸國的約」、B「兩律法的重疊」和 D「登山寶訓（論彌賽亞／門徒的使命）」用各自核實的教授來源。C「登山寶訓的文學結構」使用編輯署名。
- 有圖的投影片在生成時只填一個 `diagram_ref`，對應論證層提供的圖。程式查這張圖是否連到本張投影片的陳述句，並帶入圖檔。

## 3. 出場和播放

- 以 Claim 在保留原文中的陳述句為第一選擇。若沒有可定位的陳述句，可用投影片中直接指向該 Claim 的要點句。只有論據連接而找不到這兩種句子時，圖留待其他有陳述句的段落。
- 圖歸在含該句的投影片，沿用字幕的時間換算。圖由該句開始才顯示，包含跳播進入的情況。到了別張投影片或另一段錄音，顯示由當前錄音所包含的陳述句重新決定。
- 每張投影片有一張圖或沒有圖。各張圖跟自己的投影片播放。
- 用深色背景和可換行的文字呈現四張已核對的圖。文字直接取自 SVG；版面依原圖分支、包含或重疊的關係重排。手機上圖中文字至少 14 CSS px，播放到該句時即可看到整張圖。
- 空間充足時一起顯示圖和要點。小手機與較密的圖優先保留圖，暫時收起要點。小手機播放圖時縮短字幕區，保留字幕和播放控制。

## 4. 驗收

| 案例 | 可接受結果 |
| --- | --- |
| 第 1 講的結構圖 | C、D 各自放在相關投影片，保留各自圖中的文字與層次 |
| 第 2 講的 A、B | 各在自己的 Claim 陳述句出現，兩個約的並列與兩律法的交疊清楚可辨 |
| 有連接但沒有保留的陳述句 | 不顯示圖；無關的 Evidence 要點不能決定出場 |
| 同張投影片被剪成兩個播出片段 | 圖只在包含出場句的播放片段顯示 |
| 更正版的論證層 | 只有在更正憑證與原始候選都相符時，才能沿用原始分組 |
| 來源證明或圖檔更動 | 署名無法確認時不選圖；已綁定的圖檔若不符 SHA-256 或安全校驗，停止建立該版本 |
| 320×568、390×844 及桌面 | 核對未到時間、跳到時間之後和切段。用四張實際圖確認正文大小、深色背景、完整圖落在可見範圍；字幕與播放控制留在畫面 |

圖的取材與出場納入既有 Slide Eval。整體聆聽 Eval 另核對圖落在實際錄音片段的發言句，瀏覽器量測與其他介面證據共同綁定同一份聆聽目錄。更新論證時，傳入本次目標版本對照表 `--expected-versions`，舊版資料須列為尚待更新。瀏覽器已有原證據時，以 `node web/evals/listening-diagrams.cjs <catalog.json> <browser-evidence.json>` 補入測量，再把產出的 JSON 交給 `chapter_listening_eval`。完整報告仍要核對資料版本及其他聆聽檢查。

## 5. 成品的語義 Eval

生成稿先通過程式檢查，再把實際會顯示的投影片、同版原文與論證交給語義 Eval。逐張驗收忠實、承重內容、時間和已讀經文。標題一換張就可見，結論和故事結果須等到說出時才顯示。要點使用其全部實質意思已說出的句子。對比和首尾呼應應保留兩端的理由與結論。

用 `python -m backend.pipeline.chapter_slide_eval <slides> <selection>` 匯出成品和檢查清單。將每張、每項的判定及原文依據逐條寫入同版 Eval 檔。新增或變更成品時核對受影響的判定，沿用已核對的其餘紀錄。用同一命令的 `--verify <receipt>` 查投影片與選材版本以及判定是否完整。

新稿的聆聽 Eval 和發布共用這份檔案。單元資料把它存為 `<lecture>.semantic-eval.json`，與 `<lecture>.slides.json` 及 `<lecture>.selection.json` 放在一起。程式查版本雜湊與每張的驗收項目，發布時沿用已完成的驗收。既有已發布稿仍依其原有審核紀錄讀取。實際成品的正反例存於 `backend/tests/fixtures/chapter_slides/actual_candidate_eval_gold.json`。
