# 逐節聆聽軟刪除 Eval

> **讀者**：Developer、神學編輯。
> **類型**：流程。
> **狀態**：當前。程序檢查已接入統一聆聽 Eval，另有實際瀏覽器檢查。
> **與代碼對齊**：未核對。
> **權威範圍**：軟刪除的設計審查與實作驗收。設計見[逐節聆聽的逐字稿軟刪除](./listening_soft_deletion_design.md)。

## 1. 驗收方法

設計審查先用下表找出可能漏聲、誤剪、同步錯誤或不必要重工的路徑。實作後用保存的原聲、裁切證據、實際播放接口及瀏覽器重放測試。太 5:31–32 的「婚姻原則與離婚」作為真實 golden。保存的證據與兩端片段從既有音訊核對紀錄讀取，測試報告只引用保留句和區間。其他反例使用最小合成素材。所有結果須綁定原始音訊、逐字稿、裁切證據、實際交付媒體與適用的 UI 版本。

| 用例 | 驗收條件 | 證據 |
|---|---|---|
| E1 真實長刪除 | 正式逐節入口交付的音訊與已採用的裁切區間重疊為零。兩個切點各可與 golden 記錄相差最多 1 秒，且仍須在已確認的安全停頓內。用合成停頓測試相差 0.8 秒且無話語受影響可通過。相差 0.3 秒卻切字或漏播被刪話語判失敗。真實案例的前句尾與後句首均須完整。實際播放時長與保留區間總和相同，誤差在媒體時間精度內。 | 播放接口區間、實際解碼媒體、已保存的兩端語音核對 |
| E2 段內及連續刪除 | 同段的保留、刪除、再保留須分別對齊。多段相接時合併切口，保留文字每句聽到一次。整個播放段都被刪時，目錄無空卡。 | 合成含清楚聲音標記的音訊、公開目錄 |
| E3 切點不確定或無原聲 | 給出缺 cue、兩側句子重複、兩個說話者重疊，以及可證實的辨識誤植。前三類保留復核狀態，未驗證段無公開原聲回退。誤植不裁掉手邊的可聽文字。 | 合成反例、保存的定位與拒絕結果 |
| E4 跳轉及慢瀏覽器 | 在桌面及既有常規、緊湊手機佈局跑自然播放、變速、快進、倒退、拖曳、續播及舊原聲時間連結。刻意延遲播放事件並測灰色開關、章內舊段及舊聆聽入口。所有路徑都使用安全媒體。 | 網路媒體回應、瀏覽器實播、解碼音訊；實機 Safari 另記 |
| E5 切口後的畫面 | 前句高亮在前句結束，後句從後句起聲更新。投影片、要點、經文和圖用同一個原聲位置。切口前的預讀不得跨到接回後的事件，也不得預讀刪除區間內的事件。同時測「保留原聲仍支持，可重定位」與「支持僅在刪除區間，須刷新」兩個反例。 | 音訊與畫面時間軸、投影片支持句與既有 Eval |
| E6 來源或發布狀態改變 | 改逐字稿、換錄音、刪去剪裁資產、模擬發布中斷，以及嘗試啟用剪裁資產後、切換清單前剛換新版逐字稿的情況。已驗證輸出可以保留，未驗證範圍須保持安全。變更範圍以外的單元仍可播，無刪除的來源播放結果相同。 | 版本與資產綁定、正式入口讀回、模擬恢復 |
| E7 重用與無刪除回歸 | 同一來源出現在兩章只建一份剪裁媒體。同樣輸入重跑時沿用模型核對，改一個切點時只重新核對該邊界。無刪除的來源沿用現有時間、媒體和播法。 | 候選與調用紀錄差異、媒體 SHA、無刪除索引對比 |

## 2. 判定

每項適用檢查單列通過、失敗或待驗證。設計審查核對設計能否滿足條件，實作驗收重放候選結果。缺實播證據時保留待驗證狀態。實作報告併入 `chapter_listening_eval`，只讀核對既有模型和聲音證據。發布核對用通過的同一版本，驗證已核對的媒體、時間對照和播放清單是否一同啟用。

## 3. 重放真實案例

準備隔離資料後，將正式播放入口在隔離資料上的輸出保存為 `public.json`，剪裁音訊保留在同一個測試目錄的 `video/`。設定 `WANG_CUT_EVAL_DATA` 指向測試目錄，並用 `web/evals/listening-soft-deletion.cjs` 在本機播放器驗證。此檢查重放該次原聲剪裁及同一份接口回應。
