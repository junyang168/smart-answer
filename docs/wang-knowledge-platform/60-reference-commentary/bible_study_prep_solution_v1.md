## 3. 查经准备档

一次查经一个目录：`$DATA_BASE_DIR/bible-study/<日期>-<经文>/`，例如 `2026-09-25-mat-20-17-34/`（书卷用 `backend/api/scripture.py` 的简称）。**不进 git**：里面有 Carson 的页码与摘录。

| 文件 | 内容 | 谁写 |
| --- | --- | --- |
| `sources.json` | 这段经文的材料清单：Carson 相关页 `(volume_id, printed_page)`；教授相关 claim 的 `claim_id` 与所在讲道 | 机器生成，负责人可增删 |
| `notes.md` | **讨论纪要。** 每条一个编号：问题、结论、依据（Carson 页码、`claim_id`、经文）、负责人的裁定（采用／不用／下次讲） | Claude 在对话中逐条记，负责人确认 |
| `outline.md` | **范围与大纲。** 范围：这次讲哪几节经文、哪些留到下次、时间多长。大纲：几节、每节讲什么，每节列出它依据的 Carson 页码、教授 `claim_id` 和纪要编号 | Claude 根据三样材料起草，负责人批准后才写逐字稿 |
| `script.md` | 逐字稿。每段末尾用 HTML 注释标出它承载的纪要编号和来源，例如 `<!-- n12; carson v2 p431 -->`，渲染时看不到 | Claude 按节写 |
| `slides.json` | PPT 内容：每页的类型、标题、重点、经文引用、对应的逐字稿段落 | Claude 写，机器检查 |
| 生成物 | `.pptx`、`（投影片對照）.md` | 机器生成，发布时复制到 `团契/<日期>/` |

**范围与大纲为什么要单独一步。** 这次的范围是在对话里一点点定下来的：整个 20 章一次讲完太多，只有一个小时；19:27–30 要和葡萄园连在一起讲；服事一段并进 20:17–34 一次讲完；20:28「作多人的赎价」留到下次。这些决定散在对话各处，写逐字稿时没有一份清单可对，于是服事一段整段漏掉。先把范围和大纲写下来、负责人批准，逐字稿就有了可以逐项核对的依据。

`notes.md` 是这套设计的核心。这次遗漏的东西都是讨论里定下、却没进逐字稿的，有了编号，机器能查。

## 4. 流程

```mermaid
flowchart LR
    PICK["选经文"] --> SRC["生成材料清单"]
    SRC --> QA["提问与解答<br/>逐条记纪要"]
    QA --> OUT["范围与大纲<br/>负责人批准"]
    OUT --> SCRIPT["逐字稿<br/>按节写"]
    SCRIPT --> SLIDES["PPT"]
    SLIDES --> PUB["发布到团契文件夹"]
    QA -.->|"随时回头问"| SCRIPT
```

| 步 | 做什么 | 机器查什么 |
| --- | --- | --- |
| 1. 开始 | 负责人在 Claude Code（Mac 或 iPhone 远程）输入 `/bible-study 2026-10-02 太 20:28`。不带参数的 `/bible-study` 列出还没发布的准备档，选一个就从上次停下的地方接着做：读回纪要、范围与大纲、已写的逐字稿，并说明做到哪一步 | 目录建好；接着做时准备档里的文件都读得到 |
| 2. 材料清单 | 按章取 Carson 页（页记录的 `chapters` 字段）；按 `scripture_refs` 取教授 claim；列出 claim 所在讲道 | Carson 该章是否有缺页，缺了先提醒去扫描 |
| 3. 提问与解答 | 和这次一样对话。每得出一个结论，Claude 把它记进 `notes.md` 并告诉负责人编号 | 每条纪要至少有一个依据 |
| 4. 范围与大纲 | Claude 根据**三样材料**起草：Carson 相关页、教授相关讲道（claim 与原文）、`notes.md` 里的学习对话纪要。先定范围，再定大纲。负责人改到满意、明确批准后，才开始写逐字稿 | 每条「采用」的纪要都分到了某一节；每条「下次讲」的纪要列在范围的「留到下次」里；每一节至少有一个依据 |
| 5. 逐字稿 | 一节一节写，每节写完给负责人看 | 每条「采用」的纪要在逐字稿里有标记；「下次讲」的纪要只能预告、不能展开 |
| 6. PPT | 从逐字稿写 `slides.json`，生成 `.pptx` 和对照 | 每页不超过 4 条重点，每条在 32pt 下排得进一行（这次最长的一条 19 个字）；逐字稿引用的经文都在某一页上且一字不改；逐字稿每一段都在某一页的备忘稿里 |
| 7. 发布 | 复制到 `团契/<日期>/` | 目标文件在 PowerPoint 里开着就停下，先请负责人关掉 |

语气、「不引讲道」、中心真理正面点明这些是写法要求，写进 Claude 的工作说明，不做机器检查：版式能机械判断，文笔不能。

### 5.1 PPT 生成器必须保留的做法

这次的生成器写在会话 scratchpad 里，会话结束就会被清掉。2026-09-25 已把它复制到 `$DATA_BASE_DIR/bible-study/_generator-snapshot-2026-09-25/`（`lib.js` 是生成器，`deck1.js`／`deck2.js` 是两份 PPT 的内容，`qa.sh` 是渲染检查）。F11.07 从这份快照搬进仓库。

负责人 2026-09-25 对 PPT 的四条要求，下表每一条做法都是为了满足它们：

1. **字体要够大，要清晰**
2. **逐字稿中引用的经文都要出现在 PPT 上，而且不能简化**
3. **PPT 要 cover 逐字稿的所有内容，不能跳过**：逐字稿的每个要点都在某一页上
4. **每张投影片只呈现要点**：短句，不是逐字稿的句子；完整的话放在备忘稿和对照文件里。第 3 条和这一条一起才是负责人要的：要点一个不漏，句子一句不搬

下表每一条都是这次返工换来的，F11.07 已全部写进生成器：

| | 做法 | 这次出过的问题 |
| --- | --- | --- |
| 1 | **投影片只放重点**：每页最多 4 条，每条排得进一行；完整句子放备忘稿和对照文件 | 第一版把逐字稿整句搬上去，48／95 页。负责人：「基本上是逐字稿的全部内容，而不是 KeyPoints」 |
| 2 | 字号：标题 40pt，正文 32pt，经文 32pt，重点旁的经文卡 28pt，表格 26pt，结论框 30pt，单句页 40pt；字体 Microsoft JhengHei | 负责人要求「字体要够大，要清晰」 |
| 3 | 文字的语言标记改成 `zh-TW` | pptxgenjs 默认标 `en-US`，PowerPoint 按英文断行，行首出现「。」「，」「」」 |
| 4 | 逐字稿引用的经文一字不改；太长就按节拆成几页，每页标（1/6）（2/6） | 负责人要求「经文要出现在 PPT 上，而且不能简化」 |
| 5 | 逐字稿只写出处、没有引文的经文（如「太 16:21–28」），放关键的一节，全文照录，标题注明「关键经节」（D2） | 整段都放会让 20:17–34 那份多 5–6 页 |
| 6 | 读经段落已经整段放过的经文，讲到时不再单独占一页，放在重点页旁边的经文卡里 | 20:17–34 那份因此多出 3 页 |
| 7 | 经文卡的标题：跨章时只有前一段结束在该章最后一节才合并写；跨卷时用简称（提后 2:12） | 标题写成「17:22–18:5」，其实是 17:22–23 加 18:1–5；卷名太长挤进经文 |
| 8 | 表格的行高在 PowerPoint 里是最小值，放不下时要把行高整体缩小 | 一页的表格溢出页面 |
| 9 | 每节开头不单独占一页，只在该节第一页标题上方放节名，页脚也写节名 | 节标题页让页数多了一截 |
| 10 | 生成时检查逐字稿每一段都进了某一页的备忘稿，缺一段就报错 | 负责人问过「对照表里的逐字稿内容是不是被省略了」 |
| 11 | 对照文件里每页标「【第 N 页】」，并列出该页的经文 | 负责人要知道「逐字稿里如何知道对应的 slide」 |
| 12 | 用 **PowerPoint** 渲染检查（AppleScript 另存 PDF → 拆页 → 缩略图），不用 Keynote 或 LibreOffice | 负责人用 PowerPoint 放映；其他软件的字宽不同，查不出真正的溢出 |
| 13 | 发布前查目标文件是否在 PowerPoint 里开着 | 负责人开着旧版，页码对不上，以为生成错了 |
| 14 | 文件校验用装了 `defusedxml` 的 Python（仓库的 `.venv`） | 系统 Python 缺这个库，校验跑不起来 |
| 15 | 一张经文卡放了不同章的几段经文（太 16:21；17:22–23）：每段第一节都标章号，段与段之间空一行。读经段落跨章接下去（19:30 → 20:1）不算 | 负责人发布后在 PowerPoint 里自己改的 |
| 16 | 发布时，已发布的文件若在上次发布后被改过，停下，不覆盖 | 负责人 2026-09-25 直接改了两份已发布的 PPT；重建后照旧复制就会把改动冲掉 |
