只有原 action 已實際完成、Claim 的提交後像未變、過期依賴可由同批已提交 ChangeSet 解釋時，
才為失效的原目標及本批新建 Claim 產生固定的只讀核對請求。
請求沒有修改、新建或退休許可，不預留 Claim ID，完整來源和一跳上下文規則不變。

初輪 Opus，必要時最多一次 GPT 判定和一次 Opus 複核。
同一交接點只保存一份不可改寫的清單與 action/root，續跑不換址重新購買裁決。

尚有效者不呼叫模型。無來源、hold、來源／外部變更、目標本身另有改動、缺失原審閱、
新實質異議或答覆不確定時仍保留未完成。新工作者核對準備時綁定的實際範圍與 SQL pins，
版本改變在呼叫前拒絕。只讀核對本身不改共用內容，不會再次使其他 Claim 失效。

每段通過後保存完成檢查點。恢復時同時核對實際 SQL 原 action 已完成及原 request/root；
不能僅憑一個完成檔案跳過未執行的操作。
檢查點只保存歷史交接，不取代最後全批當前資格。
因此後段提交後中斷，可以回到後段完成必要核對，不重啟已完成的前段內容修改。
相同結果的零呼叫續跑保留原結果檔字節，已消費的歷史 SHA 綁定不被打壞。
