# 第三、第四讲多用途设计验证规范 v1

## 一、为什么用这两讲

这两讲同时包含连续经文释经、跨经文神学论证、听众问答、重复讲述、原文与文体判断、生活应用和未回答问题，适合暴露模型是否只为某一种文章服务。

本试验的任务不是把两讲整理成最终专题目录，而是回答：**一套共享知识结构能否忠实保存教授的思想过程，并支持多种产品，而无需为每种产品重复抽取一遍资料？**

## 二、五项验证实验

| 实验 | 验证的问题 | 成功标准 |
|---|---|---|
| 马太 17 释经 | 能否支持逐段、连贯、不过度岔题的释经 | 论断可溯源；缺口不补写；专题材料只作短注或链接 |
| “人子”跨讲专题 | 能否由全库普查找范围、由精细抽取建立证据 | 显示来源成熟度；普查线索不得直接出版；同一主张可服务双轴 |
| 问答链复原 | 问题是否会被文章结构吞掉 | 问题、回答、部分回答和未回答边界均保留 |
| 搜索与智能问答 | 能否回答具体问题并给出推理与来源 | 区分教授主张与编辑归纳；返回原始定位与当前语料范围 |
| 释经方法研究 | 能否跨篇累计教授反复使用的方法 | 方法有多个实例、频率和来源；允许随全库材料修订 |

## 三、架构验收问题

1. 每个实质主张是否可回到原始讲道的精确片段？
2. 问题、证据、推理和结论是否仍可区分？
3. 同一主张是否能被多个产品引用而不复制成多份真相？
4. 编辑归纳和篇章判断是否明确区别于教授主张？
5. 问答是否保留原有对话边界？
6. 局部样本是否清楚标出“不代表全库完成”？
7. 新讲道加入后，主张、关系和专题线索是否可扩展或修订？
8. 非技术同工是否可以在一个界面完成核心审核？

## 四、完成定义

第一轮验证完成，不等于文章已经出版。必须至少达到：

- 140 个证据片段与 125 条关系完整迁移并通过结构检查；
- 五种用例都能读取同一共享知识包；
- 马太 17 编排决定被明确标为编辑计划；
- “人子”专题已有独立 Composition Plan；全库普查线索与已有详细论证资料分层显示；
- 同工能分别审核共享主张、跨讲综合和具体产品计划；
- 发现模型问题时先修模型，再扩大到其余讲道。

本规范最初只以两讲检验模型。双轴纵向验证已经将专题轴扩展到 205 篇普查范围，并以 `011WSR01` 为下一篇优先详细整理来源；详见 [双轴纵向验证 v1](./dual_axis_vertical_validation_v1.md)。
