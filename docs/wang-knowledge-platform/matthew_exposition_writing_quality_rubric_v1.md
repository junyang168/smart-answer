# 馬太福音釋經文章寫作質量標準 v1

## 1. 目的

本標準判斷一篇文章是否已經成為可供普通讀者連續閱讀的釋經文章。它不重做資料溯源、claim coverage 或連結檢查，也不容許這些技術指標代替寫作判斷。

馬太福音 1–16 章以教授釋經課筆記整理成的 `final.md` 為主要框架。這份整理稿雖由 AI 協助生成，其平實、完整、不刻意模仿課堂口吻的書面風格已經過反覆調整，應視為母本，而不是與其他講道平行的一項素材。

## 2. 硬門檻

以下任一項失敗，文章即不得出版，總分不能抵銷：

1. 母本的承重論證步驟被刪除、顛倒或壓縮成來源摘要。
2. 編輯綜合、一般神學知識或 AI 推論被寫成教授本人的主張。
3. 來源之間確有張力，正文卻把它們靜默調和，或把其中一項寫成唯一無爭議結論。
4. 資料庫 ID、候選知識、跨來源審核、coverage gap、manifest 等生產語言主導正文。
5. 普通讀者不能從段落本身跟隨「經文觀察 → 解釋 → 推論 → 結論」的鏈條。

程序性審核未通過（包括 provenance、必要經文、連結、音訊或 manifest 一致性錯誤）是另一道外部出版 gate；它不由 Editorial Review Agent 評分，也不能用文筆高分抵銷。

出版線不是總分，而是逐維度：**十個維度各不得低於其分值的 80%**（15 分項需 12，10 分項需 8，5 分項需 4），任何一項不足即不得出版；所有硬門檻均須通過。總分仍然計算並呈現，但只是給人讀的參考值，不是關卡。

改成逐維度是因為總分會把弱項平均掉：太16:21–23 首輪 baseline 總分 81/100，同時在「一般讀者可讀性」「精簡而不壓縮」「牧養神學落點」三項分別只得 7、3、3（門檻 8、4、4），靠其餘七項墊到及格。十個維度是十項各自成立的要求，不是可以互相折抵的分項。

### 深度校準

claim、step 與 provenance 全部覆蓋，只能證明材料有被提到，不能證明文章已把論證寫好。Reviewer 必須逐節確認普通讀者能跟上「觀察了甚麼 → 為甚麼重要 → 如何推到下一步 → 結論受甚麼限制」。若文章只把 Petros/petra、弗 2:20 與「基督是根基」並列成幾句摘要，即使技術 audit 全部通過，「母本保全」「釋經推理鏈」「精簡而不壓縮」也不得達到門檻。

## 4. 可操作的文字指標

以下是預警，不是機械定罪；Editorial Review Agent 必須回到上下文判斷：

- 「王教授指出／認為／強調」只在首次歸屬、切換來源或標明張力時使用；同一連續段落不反覆點名。
- 「編輯說明／導讀／資料說明」原則上每篇不超過兩處，且不能承擔主要論證。
- 不在讀者正文出現 `DK-`、decision、candidate、coverage、manifest、跨來源審核等內部詞。
- 不要求每個 composition decision 對應一個可見標題；多個 decision 可以由同一連續段落覆蓋。
- 原文觀察只有在刪除它會削弱結論時才進正文；形式細節可進註腳，但推理作用必須留在正文。

## 5. 太 16:18 的首個回歸案例

母本的承重鏈至少包含：

1. `Petros` 與 `petra` 有關，但詞形與陰陽性不同。
2. 這個區別使「磐石」不能不經論證就等同彼得本人。
3. 弗 2:20 的「使徒和先知」共用一個定冠詞，形成共同的根基性見證。
4. 使徒和先知的見證指向作房角石的基督；因此基督是教會終極的根基。
5. 其他講授把正面所指著重在彼得的認信或所領受的真理；這應在母本論證完成後作為真張力自然交代。

失敗示例：

> 筆記整理稿較強調基督本身；另一些講授則較強調彼得的認信。兩種說法都不是彼得本人。編輯部保留這項張力。

這段溯源可能正確，卻刪掉了母本的推理，並用審核報告語言取代釋經。

合格示例：

> 耶穌說：「你是彼得，我要把我的教會建造在這磐石上。」希臘文在這裡用了兩個彼此相關卻不完全相同的詞：彼得是 *Petros*，磐石是 *petra*；前者配合彼得的男性名字，後者則是陰性名詞。這個差別本身還沒有回答「磐石究竟指甚麼」，卻提醒我們，耶穌的話不能不經解釋就縮成「教會建造在彼得這個人身上」。
>
> 以弗所書 2:20 提供了進一步的線索。保羅說教會建造在「使徒和先知的根基上」，並且「有基督耶穌自己為房角石」。原文把使徒和先知放在同一個定冠詞之下，重點不是抬高某一位使徒，而是把他們共同的見證連在一起；這見證所指向的中心，正是基督。使徒可以在根基性的見證中有分，教會終極的根基卻不是使徒個人的身分和權位，而是他們所見證的基督。
>
> 另一些講授把「磐石」更直接地說成彼得的認信，或他從基督領受並傳下來的真理。這與前面的解釋有共同的否定面：教會不是建造在彼得個人之上。兩者的著重點仍不完全相同——一個直接指向基督，一個著重對基督的認信與真理。文章應保留這個差別，不必把它硬壓成一句看似整齊、其實超過材料的公式。

## 6. 審核輸出要求

Editorial Review Agent 不只給總分，還必須：逐維度說明證據；逐主要 section 判斷母本步驟是否完整；列出可執行 finding；區分 blocking 與 non-blocking；指出需要退回 Composition Agent 的結構問題。程序 audit 和寫作 rubric 分開呈現，任何一方不得替代另一方。

初审使用不超过 40 KiB 的独立 `EditorialReviewPacket`，不传送完整 knowledge snapshot、CompositionPlan 或 base manuscript。修订后使用 `FinalDeltaReviewPacket`，只检查 changed paragraphs、前次已验证 review、accepted findings、dispositions、受影响维度与 manuscript SHA。未受影响维度不得由模型重新评分，只能从 SHA 绑定且已通过本地校验的 baseline 继承；总分、各维度最低线与 hard failures 一律由程序合并后重新计算。所有 finding anchor 在模型返回后立即与当前稿逐字核对，delta finding 还必须落在修改后的段落内。
