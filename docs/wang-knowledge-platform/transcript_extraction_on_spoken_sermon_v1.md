## 二、三項檢查

### 2.1 代言：沒有一句被寫成教授的主張

第 8 段（S0009，3,706 字）裡教授模擬 Wrede 說話，Wrede 的說法裡又模擬門徒說話，門徒的話裡再模擬耶穌說話（「我不准你講話，Shut up！」）。三層。

抽取把整片代言收在一個 **position node** 上：

```
position  彌賽亞秘密理論：耶穌不是彌賽亞，門徒為維持生計而創造彌賽亞宣稱及保密傳統
attribution  教授所稱的德國教授及不信派學者
fragments  S0009 的 34–101、160–476、590–1197（三段，共 990 字）
```

第三段 590–1197 正好蓋住嵌套最深的那一片（門徒對話與其中的耶穌命令）。第 3 節裡**沒有任何 evidence_step 的錨點落在這三段之內**；該節 28 條 step 全部 `speaker=professor / stance=asserted`，取的都是代言之外的教授本人語句。反駁該理論的是 CL006，並以 `opposed_position_ids` 指回這個 position。

全篇同樣的檢查：13 個 position 共 25 段錨點（1,659 字），只有 4 條 evidence_step 的錨點與它們重疊，逐條看過：

| step | speaker / stance | 錨點 |
|---|---|---|
| P01-E010 | professor / **opposed** | 「不是給彼得說，『彼得你不管你做什麼事，你決定，我們天上就聽你的話。』」 |
| P02-E019 | **quoted_source** / opposed | 「這個福音只要給猶太人，外邦人沒有資格領受福音的。」 |
| P01-E006 | professor / asserted | 「這個磐石不是建立在彼得這個人身上」 |
| P01-E032 | professor / asserted | 「那他們不是隨便『我喜歡赦免誰，誰就赦免了』」 |

四條都是**否定句本身**：前兩條用 stance 標了立場，後兩條是教授說「不是……」時句子裡包含了被否定的說法。沒有一條把代言的內容當成教授的主張。

13 個 position 的 `attribution` 裡有 8 個明寫是代言或轉述：「被教授以模擬語句表達並反駁的權柄解讀」「教授戲劇化代言彼得先前的猶太觀念」「教授自述早期的錯誤想法，以反諷方式表達」……全篇 32 條 claim 有 15 條帶 `opposed_position_ids`。**母本上少見的 `positions` / `stance` / `discourse_role` 這組欄位，在逐字稿上是主力。**

全篇 step 的 speaker/stance 分佈：`professor/asserted` 110、`professor/opposed` 2、`quoted_source/quoted` 2、`quoted_source/opposed` 2、`professor/questioned` 1。

### 2.2 重複：章節內不會變三條，跨章節會

同一個 Wrede 論點在 S0009 裡繞回來講三遍（34、160、590 三處）。結果是**一個 position 三個 fragment**，不是三條 claim。第 2 節另有 3 條 `duplicate_of` 排除（「為什麼奧祕？」「為什麼？」等重複追問），由模型自己標出，並在理由裡指明已被哪一條涵蓋。**章節內的重複收斂。**

跨章節不收斂。教授在第 1 節講過「磐石不是彼得」，第 3 節從「撒但，退我後邊去」再講一次，兩節各產出一條：

- 第 1 節：`磐石不是彼得本人，而是彼得的信仰及他對耶穌的準確認識`
- 第 3 節：`磐石不是彼得這個人本身，耶穌不會把教會建立在一個隨即因只關心人的事而被稱為撒但、仍然靠不住的人身上`
- 第 3 節：`教會建立在彼得所表達的信仰，即耶穌是基督、是神的兒子……`

同一個命題兩處各佔一列。這是分段抽取的結構性後果——`combine_sections` 按設計沒有合併步驟——與 #98 在母本上量到的同一件事（61 條裡約 6 條跨章節重複）性質相同，不是逐字稿特有的。32 條裡約 2 對，比例低於母本。**消重屬於複審與裁決的職責，不在抽取端補。**

### 2.3 `not_extracted` 的理由分佈：不是敷衍

| | 母本 v3-sections | 本逐字稿 |
|---|---:|---:|
| 排除條數 | 64 | 204 |
| `not_exegesis` | 64（100%） | 18（8.8%） |
| `background_only` | 0 | 178（87.3%） |
| `deferred` | 0 | 5 |
| `duplicate_of` | 0 | 3 |

母本 64 條全是標題與經文出處標註；逐字稿以 `background_only` 為主，且集中在該集中的地方：S0008（教授談自己為何不讓錄音）60 條、S0009（阿茲伯里教書與某教會青年事工的長篇故事）98 條。理由寫得具體到可以覆核，例如「回顧前一日內容，未承載本段論證」「未具體指明內容的過渡問題」。卡片預期的分佈出現了。

值得注意的是那則長故事**不是整片丟掉**：故事末尾教授自己下的結論（「所以為什麼我一天到晚講，這個深度解經很重要……根基打好之後，教會就很穩固」）成了 CL010，由 E020–E022 支撐；故事其餘部分進 `background_only`。一段離題敘事留下一條 application claim 與九十幾條有理由的排除，是這裡該有的形狀。

## 三、覆蓋率該怎麼讀

**「答覆率」才是驗收指標，覆蓋率不是。** 每一句要嘛被記錄覆蓋（represented），要嘛有一條寫明理由的排除（answered），兩者皆無才是問題（unanswered）。

| | 句數 | represented | 有排除理由 | 無人答覆 | 答覆率 | 實質散文 represented |
|---|---:|---:|---:|---:|---:|---:|
| 第 1 節 | 53 | 46 | 5 | 2 | 96.2% | 90.5% |
| 第 2 節 | 225 | 198 | 26 | 1 | 99.6% | 95.9% |
| 第 3 節 | 323 | 149 | 173 | 1 | 99.7% | 49.2% |
| 全篇 | 601 | 393 | 204 | 4 | 99.3% | 70.8% |
| 母本（對照） | 208 | 144 | 64 | 0 | 100% | 97.7% |

四句無人答覆的，全部是三到五個字的插語：「對不對？」「錯！」「應該知道。」「為什麼？」

第 1、2 節的實質散文覆蓋率（90.5% / 95.9%）貼近母本的 97.7%——**論證密集的口語，抽取表現與母本材料相當**。第 3 節掉到 49.2%，掉的位置全在那則故事，而那 121 條散文句每一條都帶著 `background_only` 的理由。在這裡把它拉回 97% 才是失敗。

## 四、順帶量出來的：計分板在逐字稿上從沒跑過

第一次跑第 3 節，抽取成功，但覆蓋率報告掛了：

```
{"coverage": "...", "available": false,
 "reason": "ValueError: invalid literal for int() with base 10: 'subtitle-1778084124190-0'"}
```

`sentence_ledger` 的全部驗證都在母本上做的，逐字稿這條路一次都沒走過。三個缺陷，都只在逐字稿上發作：

1. **`load_segments` 拿逐字稿自己的 `index` 當段落鍵。** 那個欄位是該段起始的字幕行號（`1, 38, 51, …`），不是位置；編輯器插入的 `##` 段落更是字串 `subtitle-<epoch>-<n>`，`int()` 直接拋錯。115 份已發布逐字稿裡 24 份含這種段落——而它們正是**能靠 `##` 分節、不必問模型要邊界的 25 份裡的 24 份**。抽取端的 `segment_locator` 一律用 `S{position+1:04d}`，`source_coverage_view` 也早就按位置編號；改成同一套。
2. **排除記錄寫的是逐字稿 ID，計分板讀的是套件發佈的 `SRC-<slug>`。** 於是 173 條排除**沒有一條**對得上任何句子（母本 64/64 全對得上，因為母本的 descriptor 兩邊同名）。修法是兩邊都叫同一個 `published_source_id()`。
3. **同段內重複句子的序號算錯。** `exclusions_from_audit` 只數已排除的同文句子，計分板數的是全部同文句子。S0009 有兩句「為什麼緣故？」，排除第二句卻定址到第一句——那一句已被 fragment 覆蓋，於是它同時是 represented 和 excluded，而它的孿生句變成無人答覆。改成按全節句序定序號。

修完：173/173 對得上，`represented + excluded` 不再重疊，母本 v3-sections 的數字一字未變（129/132、97.7%）。三個缺陷各有一條測試，未修時三條全紅。

## 六、結論

1. **代言沒有被當成教授主張**，包括三層嵌套那一片。`positions` / `attribution` / `stance` 這組欄位在逐字稿上被真正用起來（13 個 position、15/32 條 claim 帶反對關係），而它們在母本上幾乎閒置。這是最危險的一類錯，實測沒有發生。
2. **章節內的重複收斂成一個 position**，不是三條 claim。跨章節重複仍在，但那是 #98 已經在母本上量過的同一件事，屬複審職責。
3. **`not_extracted` 的理由分佈與母本完全不同**（87% `background_only` 對 100% `not_exegesis`），且集中在離題段落，理由具體可覆核。模型沒有敷衍。
4. **答覆率 99.3%，第 3 節 99.7%**；未答覆的 4 句全是三到五字插語。第 3 節散文覆蓋率 49.2% 是對的，不是失敗。
5. **8,106 字 / 323 句沒有量到失效邊界**，所以沒有寫任何「章節過大就再切」的機制。要寫的話，得先量出一個真的會失效的規模。
